# 本机连续跌倒运行时验收 v2

日期：2026-08-06

## 目标

修复原运行时只能在确定性 `TransitionDetector` 已发出事件时才调用 MIL 的时序缺陷，并验证本机完整链路在不同采样频率下是否达到演示稳定性门槛。

完整链路：

```text
INT8 MoveNet
  -> 鼻子保留的 INT16 姿态头
  -> 7.5 Hz 姿态平滑
  -> 确定性 TransitionDetector
  -> 每 250 ms 连续跌倒窗口评分
  -> 事件锁存与恢复
  -> fall_like_transition
```

## 原始基线

原实现只在确定性 detector 已产生 `uncertain_transition` 时，才使用 MIL 升级事件。

12 FPS 留出回放：

- 跌倒：2/15，13.33%
- 正常误报：1/10，10%
- 重复事件：0

该结果未通过本地演示 Gate。

## v2 状态机

### 连续评分

每 250 ms 对最近窗口独立评分，不再依赖确定性 detector 是否恰好发出事件。

### 冲击分支

需要同时满足：

- 初始身体中心 `center_start <= 0.65`
- 身体中心下降 `center_drop >= 0.10`
- 高运动占比 `high_motion_ratio >= 0.22`
- 躯干角度范围 `torso_range_deg >= 55`
- `peak_motion_speed >= 0.55` 或 `max_downward_center_speed >= 0.65`

### 模型与低位稳定分支

需要同时满足：

- 模型概率 `>= 0.95`
- 中心下降 `>= 0.18`
- 存在低位锚点
- 最终躯干角度 `>= 45°`
- 躯干角度范围 `>= 60°`
- 高运动占比 `>= 0.08`
- 最大向下速度 `>= 0.50`

该分支拒绝了下跪动作中“中心下降明显但躯干最终仍接近直立”的情况。

### MIL 使用边界

MIL 分数继续写入事件证据，但不再允许在缺少结构确认时单独把 `uncertain_transition` 升级为跌倒。普通躺下曾在 MIL 上获得高分，因此无结构复核的单独升级会产生误报。

### 去重与恢复

- 第一次跌倒后锁存。
- 至少保持锁存 10 秒。
- 只有检测到站立或坐姿、运动为静止/低速、姿态持续至少 5 秒时才恢复。
- 场景或 session reset 会立即清空锁存和窗口。

## 工程 Gate

仅用于当前比赛本机演示，不是医疗或真实世界准确率标准：

```text
留出跌倒触发率 >= 80%
留出正常视频误报率 <= 5%
重复事件率 <= 5%
```

## 结论边界

当前可表述为：

> 在现有本地归档视频和当前 INT8/INT16 bundle 上，连续跌倒运行时已通过 12、24 和 30 FPS 配置的比赛演示工程 Gate。

仍不得表述为：

- 真实家庭环境跌倒准确率；
- 医疗级跌倒检测；
- 对未知人物、机位、遮挡、光照和房间的泛化能力；
- fall precision、recall 或 F1；
- 所有类型跌倒都能稳定检测。

当前数据中的 15 个留出跌倒片段仍来自同一跌倒合集视频，10 个正常视频也以动画动作素材为主。下一步必须补真人摄像头独立测试集，尤其需要普通躺下、下跪、捡东西、快速坐下和遮挡动作。
