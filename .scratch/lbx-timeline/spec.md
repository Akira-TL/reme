## 1. 目标与假设

把家属端首页内嵌的简短时间线提升为底部导航中的独立「时间线」入口，让家属可以按日期查看本次公开演示会话内已经发布的结构化家庭状态，并展开事件来源与隐私说明。

本轮假设：在不新增后端或 Relay 合同的前提下，当前 `reme-demo-state/v1` 的权威快照足以验证独立时间线的信息架构、日期导航、空状态和事件展开交互。

Go 条件：

- 时间线成为独立底部入口，首页不再重复展示同一列表；
- 日期条可切换，未来日期不可选，无记录日期显示诚实空状态；
- 当前会话内的关键状态变化可去重累积，不把 keepalive revision 当成新事件；
- 页面明确说明数据仅来自当前公开演示会话，刷新或换房间会清空；
- 自动测试、lint、build 与 390×844 浏览器视觉 QA 通过。

No-Go 条件：

- 为了填满页面而预置未标注为演示的生活事件；
- 把旧快照、离线状态或普通 Viewer 连接数描述为老人当前生活事实；
- 在没有身份认证、保留期、授权和查询合同的情况下持久化跨天家庭历史。

## 2. 视觉目标

来源：用户提供截图左侧的按天时间线面板，以及现有 `frontend/src/assets/reference/home-normal.png` 的家属端视觉体系。

- 保留暖白底、橙色强调、圆角卡片和细竖线节点；
- 顶部使用一周日期条，选中日为橙色实心状态；
- 事件条目显示时间、分类、标题和摘要，点击后展开来源、房间与能力状态；
- 底部导航从三项扩为四项：`首页 / 时间线 / 看板 / 设置`；
- 不新增 raster 资产；标准界面图标继续使用项目已有 MUI Icons。

## 3. 数据边界

本轮不接数据库。

原因：

1. 当前 Viewer 是固定公开演示房间，规格明确无身份认证；持久家庭历史会扩大隐私暴露面。
2. Relay 的 Durable Object SQLite 只保存最新权威状态、命令回执和短期媒体授权，没有已接受的家庭时间线 schema 或查询接口。
3. 跨天时间线需要先冻结事件分类、时区、授权、保留期、删除、分页和家庭访问控制；这些不是纯前端细节。

本轮数据源为内存中的当前房间会话投影：

- 输入：严格校验后的 `reme-demo-state/v1`；
- 记录：初始权威状态，以及 care、consent、scene、capture、runtime 的有意义变化；
- 去重：只按语义签名追加，keepalive revision 不产生条目；
- 生命周期：页面刷新或 `room_session_id` 变化即清空；
- 上限：最近 80 条结构化条目；不保存骨架、图片、视频、音频或自由对话全文。

## 4. 后续数据库 Gate

只有满足以下条件才进入持久化实现：

- 有身份认证与家庭级访问控制；
- 事件 schema、provenance 与版本策略已评审；
- 明确保留期、删除与老人授权；
- API 支持按家庭、日期范围、游标分页查询，并有空值/降级合同；
- 结构化事件与 MiMo 日记分开存储，日记明确标注生成来源且不得替代原始事件事实。

优先复用现有服务边界，不在浏览器 `localStorage` 中伪装成共享数据库。
