# MiMo 显式真实识别与四场景切换可行性规格

- Type: feasibility spec
- Status: accepted-for-experiment
- Capability gate: pending
- Owner: C / MiMo scene recognition
- Date: 2026-08-02
- Branch boundary: 最终交付只允许进入 `lbx`；本规格本身不授权部署
- Related: `CONTEXT.md`、ADR-0003、ADR-0005、ADR-0008、ADR-0010

## 1. 用户目标与动作语义

在现有 `日常 / 做饭 / 完全隐私 / 跌倒` 四个场景按钮之外增加一个独立动作：
**“真实识别 · MiMo”**。

它不是第五个场景，也不是向评委端打开实时原画。每次点击只做一轮有界操作：

1. 从监控端当前真实摄像头取得一个最小视觉样本；
2. 明确显示本次实际发送的是 MP4 还是 JPEG fallback；
3. 通过受控 Relay 请求 MiMo 返回一个场景提议；
4. 只有提议通过本地合同与接受策略时，才切换到现有四种展示模式之一。

四个手动场景按钮始终保留为显式 fallback。手动切换不是 MiMo 识别结果，页面和事件记录不得混淆二者。

## 2. 当前证据边界

已有证据只支持建立窄实验，不支持宣布能力已经完成：

- `.scratch/handoff/2026-08-01-mimo-api-live-test.md` 已实测 `image_url` Base64 图片和
  `video_url` Base64 MP4 可以得到 HTTP 200；该视频仅为极小合成色块，且出现颜色语义误差，
  因此只能证明通道成立。
- `.scratch/mimo-decision-interaction/results/2026-08-02-danger-link-smoke.md` 有单张合成倒地图的
  MiMo 结果与一次延迟记录；它不代表真实家庭跌倒或四场景分类质量。
- 现有公网厨房路径只在人工选择厨房后发送 JPEG 判断 `cooking`，没有验证 MiMo 从未知场景中
  自主区分 `living / kitchen / bathroom / fall`。
- 目标手机、真实机位、真实光线下的准确性、拒判率、重复稳定性、请求时延和视觉用量都尚未测量。

因此本能力的 Gate 保持 `pending`。不得把端点可调用、Schema 单测或合成素材结果写成真实四场景验收。

## 3. 研究问题与假设

### 研究问题

在比赛指定手机、机位和四段真实演示动作中，一次显式的约 2 秒 MP4（或透明 JPEG fallback）
能否让 MiMo 给出足以驱动展示模式的场景提议，同时保持失败可见、无隐式二次上传，并且完全不改变
既有跌倒告警状态机？

### 零假设 H0

在目标条件下，单次最小样本不足以稳定区分四个场景，或其时延、拒判、隐私/用量成本不适合作为
路演自动切换入口；此时继续使用四个手动按钮。

### 备择假设 H1

在固定路演条件下，单次最小样本可产生可复现且可拒判的场景提议；本地策略接受高质量提议后，
可以只切换既有展示模式，并在任何模型失败时保留当前模式和手动 fallback。

该假设不涉及跨家庭泛化、医疗跌倒检测、身份识别、真实家具复原或持续视频理解。

## 4. 单次采样协议

### 4.1 前置条件

- 只允许当前有效控制租约调用；浏览器不得直接持有或调用 MiMo API key。
- 摄像头未启动时，点击动作可以在同一用户手势中请求/启动摄像头；拒权或无有效画面时显示
  `unavailable`，不得切换场景。
- 录制、上传和等待结果期间禁用重复点击；同一时间最多一轮在途请求。

### 4.2 默认 MP4

- 默认在内存中录制约 2 秒 MP4，随后只发起一次受鉴权 HTTP 请求。
- 本轮不冻结分辨率、码率、字节上限或 MiMo `fps` 参数；它们必须在 Pilot 中连同真实请求大小记录，
  再由 Gate 决定。实现仍必须设置明确硬上限，拒绝无界请求。
- 录制结束前不得上传分片；不得把摄像头流改成持续上传。

### 4.3 透明 JPEG fallback

- 如果目标浏览器不支持 MP4 MediaRecorder、录制失败或没有得到有效 MP4，则只捕获一张降采样 JPEG。
- UI 在发送前或发送时明确显示“本次使用 JPEG 关键帧 fallback”，结果证据记录 `sample_type=jpeg`。
- 一次点击最多发送 MP4 或 JPEG 中的一种。MP4 已经提交后若网络或模型失败，不得静默再发 JPEG；
  用户可看到失败并主动再点一次。
- 本 Gate 不接受 WebM 静默替代，因为 MiMo MP4 通道有现有实测，而目标浏览器的其他视频容器尚无同等证据。

### 4.4 生命周期与审计

- 原始 Blob、ArrayBuffer、Base64 和临时 Object URL 只存在于本轮内存生命周期；请求完成、取消、超时、
  会话变化或组件卸载后立即释放引用。
- 原始媒体不得写入 `localStorage`、`sessionStorage`、IndexedDB、Cache Storage、日志、Durable Object、
  KV、事件 envelope 或仓库。
- 只记录脱敏元数据：`request_id / session_id / sample_type / byte_count / started_at / outcome /
  model / provider_status / latency_ms / classification`。不得记录媒体正文。
- 监控端必须显示何时采集、实际发送类型、请求中、结果、低置信/拒判和失败状态。

## 5. 实验响应合同

MiMo 内容使用精确字段集合：

```json
{
  "classification": "living | kitchen | bathroom | fall | uncertain",
  "confidence": 0.0,
  "reason": "仅描述本次样本中可观察到的依据"
}
```

- `confidence` 必须为有限的 `[0, 1]` 数；当前没有校准证据，不能把它称为真实概率。
- `reason` 必须简短且只描述可见线索，禁止诊断、身份、情绪和意图推断。
- 非精确字段、越界数值、非法 JSON、空理由和未知枚举一律视为 `unavailable`。
- Relay 可以在响应外层补充 `request_id / model / latency_ms / sample_type`，但不得让模型自行声明这些字段。
- 该合同只服务本次 feasibility Gate，不冻结永久产品事件 Schema。

## 6. 提议接受与模式切换

| MiMo 结果 | 本地行为 | 明确禁止 |
|---|---|---|
| `living` | 达到 Gate 后冻结的接受条件时，只发布现有 `scene_state(living)` | 不开放原画，不生成关怀卡 |
| `kitchen` | 只切到现有做饭展示模式 | 不等于识别到 `cooking`，不生成家庭心跳，不代表本人同意分享 |
| `bathroom` | 只切到现有完全隐私模式，继续 fail closed 为纯骨架 | 不开放环境图、真实视频或媒体按钮 |
| `fall` | 只切到现有跌倒展示模式/候选叙事 | 不创建、升级、解除 `alarm_state`，不签发 `fall_emergency` grant |
| `uncertain` | 保留当前模式，显示未切换原因 | 不猜测最接近的场景 |
| 低置信或不可用 | 保留当前模式并显示降级 | 不自动重试，不切换 |

接受阈值尚未实测，不能在本规格中伪造。Pilot 必须先记录各类置信分布与错误类型，冻结阈值和
接受规则后再跑留出素材；Pilot 数据不能充当最终 Gate 结果。

手动场景按钮优先级高于在途提议：手动点击、控制会话变化、停止采集或释放控制权都使本轮结果过期；
迟到结果必须忽略，不能覆盖较新的人工选择。

### 跌倒安全不变量

MiMo 的 `fall` 只是展示层场景提议。真实问询、规则倒计时、家属告警、解除告警和媒体授权仍完全由
ADR-0005、ADR-0007、ADR-0008 的姿态/回应/确定性规则控制：

- MiMo `fall` 不得提前报警或开放真实视频；
- MiMo `living/kitchen/bathroom/uncertain` 不得取消、降低或隐藏已有问询/告警；
- MiMo 超时、不可用或迟到不得暂停规则计时器；
- 代码与测试应使自动场景路径无法构造 `alarm_state` 或 `media_grant`。

## 7. 完全隐私场景的显式例外

完全隐私模式默认不产生任何自动视觉采样。用户在该模式下再次点击“真实识别 · MiMo”，即明确请求
发送**这一轮**最小样本，以判断是否切换到其他展示模式；页面必须在点击区域和请求状态中披露这一点。

一次显式采样结束后仍不得排定下一次采样。由于该动作会把所选样本发送给 MiMo，对外只能声称：

- 家属/评委端在完全隐私模式只看到骨架；
- 没有后台连续上传；
- 操作者主动点击时会向 MiMo 发送一次最小视觉样本。

不得声称“完全隐私时任何云端都从未看到像素”。如果未来要求该更强口径，退出隐私模式必须改用
本地识别、预配置区域或人工按钮，不能依靠云端 MiMo。

## 8. 不得产生的级联调用

一次“真实识别 · MiMo”点击必须对应至多一个视觉请求。场景切换本身不得排定下一次自动场景请求，
也不得因为切到 `kitchen` 而无提示地触发另一个视觉分类请求。

现有厨房 `cooking` 识别与本场景提议是两个独立可行性问题。若保留厨房活动识别，它必须拥有独立、
可见的触发和隐私说明；不得把自动切到厨房包装成“正在做饭”，也不得让第五动作的单样本承诺失真。

## 9. 实验设计与证据输出

### Pilot（只校准合同和运行路径）

- 在目标手机验证 MP4 录制、JPEG fallback、请求上限、取消和内存释放。
- 用四场景真实片段和困难负例记录原始提议、置信度、理由、时延、字节数、usage 和错误。
- 基于 Pilot 冻结提示词、模型参数、接受阈值、素材窗口和停止条件。

### Holdout Gate（能力裁决）

- 使用未参与 Pilot 调参的目标手机素材，至少覆盖四个场景、真实场景切换和困难负例。
- MP4 与 JPEG fallback 分开报告，不能把两种输入混成一个数字。
- 同一固定输入应重复调用，以暴露标签漂移；调用次序和失败不得被删改。
- 记录分类混淆矩阵、每类 precision/recall、`uncertain`/低置信保留率、错误切换、重复一致性、
  首次 Schema 通过率、请求 P50/P95、发送字节、模型 usage 与实际重试数。
- 原始素材可作为明确同意的本地临时实验夹具，但不提交仓库；结果文件记录素材哈希、测试条件和标注。

建议结果位置：

- `.scratch/four-scene-live-demo/results/<date>-mimo-auto-scene-pilot.md`
- `.scratch/four-scene-live-demo/results/<date>-mimo-auto-scene-holdout.md`
- `.scratch/four-scene-live-demo/results/<date>-mimo-auto-scene-calls.jsonl`

## 10. Gate 与 Go / No-go

### 无需模型测量即可验证的硬 Gate

以下任一失败即 No-go：

1. 一次点击产生超过一个视觉请求，或存在定时/后台采样。
2. 原始媒体进入持久存储、DO、KV、结构事件或日志正文。
3. JPEG fallback 未显示，或失败后静默发送第二份媒体。
4. `uncertain`、低置信、非法响应或迟到响应改变当前模式。
5. 手动按钮不能覆盖/取消自动提议。
6. MiMo 结果直接触发、解除或延迟跌倒告警，或直接签发媒体 grant。
7. 完全隐私模式在没有新一次显式点击时采样。
8. 切到厨房后由第五动作级联出未披露的视觉请求。

### 尚待真实测量的能力 Gate

以下项目必须先在 Pilot 中确定目标，再以 Holdout 结果评审；当前均为 `pending`：

- 四类真实素材上的正确提议与拒判分布；
- MP4 与 JPEG fallback 的差异；
- 重复输入的输出稳定性与模式误切换情况；
- 目标手机端到端等待时间是否适合路演；
- 单次请求字节、视觉 token/usage 与可接受成本；
- 真实网络失败时的降级可见性。

**Go**：所有硬 Gate 通过，真实 Holdout 证据完成，团队根据预先冻结的阈值接受质量、时延、稳定性和成本；
届时才能把第五动作作为可用实验能力开放。

**Conditional go**：合同、隐私和安全 Gate 通过，但只有 MP4 或 JPEG 一种输入达到已冻结目标；只启用已通过的输入，
另一种明确显示不可用，不做静默替代宣传。

**No-go**：任一硬 Gate 失败，或真实证据不足以支持路演自动切换。保留四个手动按钮，并把 MiMo 提议停留在
可观察实验结果，不能自动改变展示模式。

## 11. 不能声称

- 不能说 MiMo 持续观看完整视频；每次只看一次显式最小样本。
- 不能说自动场景能力已通过；当前 Gate 为 `pending`。
- 不能说端点 HTTP 200 等于真实四场景识别有效。
- 不能说 MiMo 的 confidence 是校准概率，或编造准确率、误报率、时延、费用。
- 不能说 MiMo `fall` 是医疗级跌倒检测或家庭告警来源。
- 不能说进入厨房等于正在做饭、允许记录或同意向家属分享。
- 不能说完全隐私场景从未向云端发送像素；主动点击是明确披露的一次性例外。
- 不能说固定环境图来自真实家具复原、三维重建或数字孪生。
- 不能把单一演员、手机和机位的 Holdout 结果外推到其他家庭、人物、光线或设备。
