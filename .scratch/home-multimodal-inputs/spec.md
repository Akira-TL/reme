# Home 多模态采集与火柴人输入候选记录

- Type: research
- Status: open
- Date: 2026-08-09
- Scope: Home 家中端 / 感知输入
- Decision state: 研究候选，未接受为产品架构，未授权实现

## 1. 目的

Home 的长期角色不是单一“摄像头页面”，而是全屋智能的数据采集端：从家庭本地可用的物理传感器取得事实，形成匿名骨架、位置、活动、环境状态或事件证据，再交给后续感知与关怀链路。

本记录只整理数据源与可观测边界，不修改当前 Home 页面，不新增传感器实体，不宣称任何候选能力已经接入。

当前真实能力仍是：

- 本机相机或本地视频提供画面；
- 家庭本地运行时解码画面并提取关键点；
- 麦克风仅在问询窗口参与语音交互，不是持续环境监听或骨架输入；
- 其他全屋设备、Wi-Fi CSI、雷达、深度光学和穿戴设备尚未接入。

## 2. 核心裁决：不是所有传感器都能生成火柴人

候选输入必须分成两类：

1. **骨架来源**：原始测量在目标条件下足以估计二维或三维关节点。
2. **环境证据来源**：只能证明有人、位置、移动、开门、离床、光照等事实，不能补造四肢。

如果数据源只观测到“客厅有人”，产品只能显示人体占位、位置或事件证据，不能渲染看似精确的完整火柴人。

“波”本身不是一种产品数据源。需要进一步说明它是无线电波、毫米波、超声波还是光，以及系统能否取得 CSI、点云、距离—角度、多普勒、深度图等原始测量。只有厂商给出的 `presence=true` 不足以重建骨架。

## 3. 候选数据源分级

| 物理输入 | 可取得的原始测量 | 火柴人能力 | 主要边界 | 暂定定位 |
| --- | --- | --- | --- | --- |
| RGB / 红外视频 | 图像帧 | 可估计二维关键点 | 遮挡、视线、身份隐私 | 当前 P0 |
| 深度相机 / ToF / 结构光 / LiDAR | 深度图或点云 | 有条件估计二维/三维骨架 | 仍需要视线、专用硬件和标定 | P1 候选 |
| 毫米波 / FMCW 雷达 | 距离、角度、多普勒、稀疏点云 | 专用硬件与模型下可估计骨架 | 反射稀疏、姿态反演欠约束、需实屋数据 | P1 实验候选 |
| Wi-Fi CSI / 专用 RF | 多天线信道响应 | 研究中可估计二维/三维姿态，部分条件可穿墙 | 普通 RSSI 不够；需要 CSI、多收发天线、环境标定和训练 | P2 研究候选 |
| UWB | 距离、方位、运动 | 通常只能给位置和速度 | 完整骨架需专用阵列与模型 | 环境证据优先 |
| 热成像 | 低分辨率热图或轮廓 | 可辅助轮廓和粗姿态 | 四肢重叠时关节点歧义大 | 辅助来源 |
| 超声波 / 声学阵列 | 距离、回波、运动或呼吸特征 | 通常不能稳定生成完整骨架 | 环境噪声、反射和隐私边界 | 研究候选 |
| 多个穿戴式 IMU | 加速度、角速度、方向 | 通过运动学模型可估计穿戴者姿态 | 需要持续佩戴和校准，不符合默认无感体验 | 可选辅助 |
| PIR / 门磁 / 光照 / 床垫压力 / 地板振动 | 存在、开关、压力、环境变化 | 不能生成完整骨架 | 只能作为房间和事件证据 | 环境证据 |

其中“光”必须拆开表达：普通光照传感器不能生成骨架；结构光、ToF、红外成像或 LiDAR 因为能取得空间结构，才可能成为骨架来源。

## 4. Reme 的建议顺序

### P0：保持当前真实链路

- 本地视频 → 真实关键点 → 姿态/转变候选；
- 不用合成关键点掩盖相机、模型或人体不可见；
- Home 只展示已经实际接通的数据源。

### P1：选择一个非 RGB 候选做窄实验

优先比较：

1. 毫米波雷达：先验证是否能取得原始点云或距离—角度/多普勒，而不是仅取得人体存在布尔值；
2. ToF / 深度相机：验证深度图到关节点的覆盖、遮挡和本地算力。

每次只验证一种输入，不先实现通用多模态产品架构。

### P2：Wi-Fi CSI 姿态研究

只有在可访问多天线 CSI 或等价原始信道数据时才立项。普通家用路由器的连接状态、信号格数或 RSSI 不应被写成“Wi-Fi 火柴人”。

### 环境证据层

门磁、PIR、床垫压力、光照、UWB 位置等可以用于：

- 判断可能所在房间；
- 佐证离床、进入、离开、长时间静止等事实；
- 在视觉不可用时给出有限的降级证据。

这些证据不能直接生成缺失的头、手、腿关节点，也不能单独确诊跌倒。

## 5. 进入实现前的可行性门

任何新数据源必须先回答：

1. 能否取得可重复读取的原始测量，而不是仅有厂商结论？
2. 能否与同步视频或人工标注建立本地真值，用于测量而非视觉展示？
3. 在目标房间、老人动作、遮挡和多人干扰条件下，哪些量是实测、哪些是模型推断、哪些不可观测？
4. 关节点覆盖、误差、时间连续性、端到端延迟和 `unknown` 比例是否被实际测量？
5. 断连、超时、低置信度和环境变化时，能否明确显示 unavailable / degraded，而不是继续画旧骨架？
6. 原始信号是否只在家庭本地内存处理，是否落盘，是否含可识别或可重建的个人信息？
7. 新来源是否真正改善 P0 主场景，而不是只增加演示实体和维护成本？

未通过这些门，不进入正式运行时合同、Home 数据源选择器或对外产品文案。

## 6. 后续骨架合同的最小语义要求

若未来允许多个来源共同形成火柴人，每个关节点至少要携带：

- `observed`、`inferred` 或 `unknown`；
- 来源类型与传感器实例；
- 置信度或可用性掩码；
- 源时间与新鲜度；
- 房间和坐标系/标定版本；
- 当前降级原因。

跨来源融合不能把“雷达看到躯干、门磁看到开门”包装成一副全部实测的完整骨架。界面需要区分实测点、推断点和未知点。

## 7. 当前不做

- 不把普通 Wi-Fi、米家在线状态或环境传感器包装成已具备姿态能力；
- 不把研究论文结果写成 Reme 已支持的准确率、距离、穿墙或多人能力；
- 不恢复多房间、多人追踪或情绪识别叙事；
- 不为了让 Home 看起来丰富而新增未接通的数据源卡片；
- 不在本轮修改前端、后端、骨架 schema、模型或安全时序。

## 8. 研究依据

- Zhao et al., [Through-Wall Human Pose Estimation Using Radio Signals](https://openaccess.thecvf.com/content_cvpr_2018/html/Zhao_Through-Wall_Human_Pose_CVPR_2018_paper.html), CVPR 2018：专用 RF 信号可在遮挡和穿墙条件下估计二维姿态；不能等同于普通路由器 RSSI。
- Wang et al., [Person-in-WiFi: Fine-Grained Person Perception Using WiFi](https://openaccess.thecvf.com/content_ICCV_2019/html/Wang_Person-in-WiFi_Fine-Grained_Person_Perception_Using_WiFi_ICCV_2019_paper.html), ICCV 2019：使用多天线 Wi-Fi 信道信息进行人体分割与姿态估计。
- Yan et al., [Person-in-WiFi 3D](https://openaccess.thecvf.com/content/CVPR2024/html/Yan_Person-in-WiFi_3D_End-to-End_Multi-Person_3D_Pose_Estimation_with_Wi-Fi_CVPR_2024_paper.html), CVPR 2024：多 Wi-Fi 设备三维多人姿态的实验性工作，仍是特定空间和受试条件下的 proof of concept。
- Sengupta et al., [mm-Pose: Real-Time Human Skeletal Posture Estimation Using mmWave Radars and CNNs](https://doi.org/10.1109/JSEN.2020.2991741), IEEE Sensors Journal 2020：使用毫米波雷达投影与模型估计人体关节点。
- Lee et al., [HuPR: A Benchmark for Human Pose Estimation Using Millimeter Wave Radar](https://openaccess.thecvf.com/content/WACV2023/papers/Lee_HuPR_A_Benchmark_for_Human_Pose_Estimation_Using_Millimeter_Wave_WACV_2023_paper.pdf), WACV 2023：同步毫米波雷达与 RGB 的姿态估计基准。

## 9. 本轮结论

Home 可以被定义为面向全屋智能的多模态采集端，但“多模态”是长期方向，不是当前已交付事实。现在只保留并展示真实视频采集；下一步若继续，应先从毫米波雷达或 ToF/深度相机中选择一个做窄可行性实验，再决定是否增加实体。
