# 跌倒多实例训练 v3 结果

- Date: 2026-08-02
- Evidence level: weak-supervision multiple-instance
- Status: conservative candidate model
- Model: `artifacts/pose-classification/fall-50/mil-v3/model.json`
- Report: `artifacts/pose-classification/fall-50/mil-v3/training-report.json`

## 结论

v3 是当前可用于下一阶段实时联调的保守候选确认器，但不是已经验证准确率的跌倒检测模型。

在当前视频级弱标签数据上：

- 50 个跌倒 positive bags 中产生 43 个高置信候选；
- 7 个跌倒 bags 保持低分或不满足候选门，作为 `uncertain`，不强制报警；
- 23 个正常动作 bags 中没有产生警告候选；
- 正常躺下、坐下/站起、弯腰/下蹲、下跪、俯卧撑、跳跃和稳定姿态均未越过最终阈值；
- 阈值只由 validation bags 校准，test bags 不参与权重、特征缩放或阈值选择。

以上是视频级弱标签候选覆盖与现有 hard-negative 检查，不是 precision、recall、F1 或真实误报率。8 个 test 跌倒片段仍需人工复核事件边界后才能报告正式指标。

## 数据

### Positive bags

来源：`50种摔倒.mp4`。

- 50 个片段；
- train / val / test = 35 / 7 / 8；
- 12 Hz MoveNet 抽样，共 2796 个姿态样本；
- 人体检测覆盖 97.2103%；
- 标记版视频仅用于人工审核，不作为训练像素来源。

Round 0 共得到 12 个 accepted 伪标签，其中 10 个属于 train，作为 MIL 初始化 seed。其余 positive bags 只有“该片段包含一次主要跌倒”的视频级弱标签。

### Negative bags

复用已有动作库关键点，共 23 个 bags：

- 正常躺下；
- 坐下与站起；
- 弯腰、鞠躬和下蹲；
- 稳定站立；
- 下跪；
- 俯卧撑等水平非跌倒动作；
- 跳跃和其他高动态非跌倒动作。

另外，v3 从每个跌倒 train bag 中选择远离当前候选窗口的站立前景或倒地后静止窗口，作为同视频、同人物、同画面域的负样本。最终一轮使用 126 个同域负窗口，避免模型只学习真人跌倒视频与动画负样本之间的画面域差异。

## 窗口和特征

窗口长度固定为：

```text
1500 ms
2000 ms
2500 ms
3200 ms
```

步长：250 ms。

特征只描述窗口内时序几何和运动：

- 人体中心起止位置、净下移、范围和下降速度；
- 躯干方向起止值、变化、范围和角速度；
- 经过截断和对数变换的包围盒宽高比变化；
- 关键点运动峰值、均值、P90、高运动帧比例；
- 窗口前后稳定比例；
- 平均和最低可见关键点比例；
- 几何站立锚点、倒地锚点及其先后关系。

v3 不使用 `lying_ratio`、`unknown_ratio`、`degraded_ratio` 等静态模型或质量分布比例作为学习特征，避免把旧姿态模型的动画/真人域偏差泄漏进跌倒模型。

## 保守候选门

一个窗口进入模型告警候选前，必须同时满足：

- 人体中心存在净下移；
- 相邻帧存在足够的向下速度；
- 躯干方向在窗口内发生明显变化；
- 存在持续高运动帧，而非单帧位置跳变；
- 躯干方向、宽高比变化或站立→倒地锚点顺序至少提供一项方向证据；
- 窗口前后均包含一定比例的稳定状态；
- 可见关键点和不可用帧比例通过质量门。

不满足候选门的 positive bag 保持 `uncertain`，不会被强制选为正窗口。

## 迭代式 MIL

训练过程：

1. 使用 10 个 train seed 窗口和 normal hard negatives 初始化线性模型；
2. 对每个 train positive bag，仅在通过保守候选门的窗口中选择最高分窗口；
3. 对 normal bags 挖掘最高分 hard negatives；
4. 从 positive bags 中加入远离候选的同域负窗口；
5. 重新训练并重复 7 轮；
6. 仅使用 validation bags 选择最终阈值。

最终 train positive bags 中 31 个产生候选窗口；`fall-001`、`fall-020`、`fall-045` 和 `fall-050` 在所有轮次中均没有通过候选门，保持不确定。

## v1 / v2 失败与修正

### v1

v1 同时使用了静态姿态比例和关键点质量比例。模型开始利用真人跌倒视频与动画正常动作之间的域差异，造成：

- 两个正常躺下 bags 均产生警告候选；
- V 字腹部动作产生警告候选；
- 下跪产生警告候选。

因此 v1 被否决。

### v2

v2 移除了静态姿态/质量比例，加入同视频负窗口，并压缩异常宽高比。V 字动作误警被消除，但：

- 两个正常躺下 bags 仍产生警告候选；
- 下跪仍产生警告候选。

分析发现部分正常动画存在单次位置跳变或极端宽高比变化，但缺少持续人体快速运动。v2 仍被否决。

### v3

v3 进一步要求：

- 真实净下移；
- 持续高运动比例；
- 方向或宽高比的连续改变；
- 前后稳定上下文。

结果是当前 23 个 normal bags 均无警告候选。

## 视频级弱标签结果

最终阈值：`0.711662`。

| Split | 跌倒候选 | 正常警告候选 |
|---|---:|---:|
| train | 31 / 35 | 0 / 13 |
| val | 6 / 7 | 0 / 4 |
| test | 6 / 8 | 0 / 6 |
| 合计 | 43 / 50 | 0 / 23 |

正常动作类别：

| 类别 | 警告候选 |
|---|---:|
| normal_lie_down | 0 / 2 |
| sit_or_stand | 0 / 7 |
| bend_or_crouch | 0 / 5 |
| stable_standing | 0 / 4 |
| kneeling_nonfall | 0 / 1 |
| horizontal_nonfall | 0 / 1 |
| high_motion_nonfall | 0 / 1 |
| unusual_nonfall | 0 / 2 |

这些类别数量较少，而且 normal 数据主要来自动画动作库，因此不能将 `0 / 23` 外推为真实家庭场景误报率。

## 未确认的跌倒 bags

没有产生最终警告候选：

```text
train: fall-001, fall-020, fall-045, fall-050
val:   fall-019
test:  fall-014, fall-011
```

其中部分片段没有通过保守候选门，部分存在候选窗口但低于 validation 阈值。当前策略是保留 `uncertain_transition`，而不是为了覆盖率放宽条件。

## 模型主要证据

最终模型权重较高的证据包括：

- 有序的站立→倒地锚点；
- 窗口结束处稳定倒地；
- P90 关键点运动速度；
- 人体中心变化范围；
- 锚点时间间隔；
- 躯干方向变化范围；
- 中心净下移和持续高运动比例。

这与“站立状态消失后，在短时间内进入稳定倒地状态”的目标一致。

## A 实时接入建议

当前建议是 `Conditional Go`，仅作为确定性时序检测器的高置信确认器：

```text
TransitionDetector 产生转变候选
→ MIL v3 对最近 1.5–3.2 秒窗口评分
→ 通过候选门且 score >= 0.711662
   → fall_like_transition
→ 有动作证据但未通过门或阈值
   → uncertain_transition
→ 无转变证据
   → 不输出事件
```

A 只输出 `TransitionEvent`。跌倒警告、询问、倒计时、MiMo 调用和后续通知仍由 B/C 负责。

在人工复核 test 事件边界之前，不建议让 MIL v3 单独覆盖或替代当前 `TransitionDetector`，也不得对外宣称跌倒准确率、召回率、医疗级检测或保证报警。
