# Reme 典型场景双端演示

入口：`frontend/typical-demo.html`

## 演示目标

在同一个网页里同步展示“家中智能设备端”和“异地子女手机端”。网页只申请一次电脑摄像头权限，并把同一份本地处理结果同步渲染到两个设备视图中，不上传、不录制原始画面。

## 四个场景

1. 客厅行走：真实人体姿态映射为 17 节点橙色骨架，子女端只看到骨架与正常状态。
2. 厨房包饺子：从摄像头画面中分割人物并叠加到虚拟厨房；可演示 MiMo 询问与本人同意分享，子女端即时收到片段。
3. 浴室洗澡：仅显示骨架与浴室幕布，界面明确标记隐私保护和本地处理。
4. 深夜跌倒（双模式）：**真实决策流优先**——A（8770）与 B（8100）服务在线时右上角显示"B 决策流已接入"，本地 17 点关键点直传 A、A 判定跌倒候选、B 推送问询（预置语音自动播放）并升级家属告警，面板按钮即真实回应（我没事→化解；子女端确认→回执关闭），紧急画面是否展示原画严格跟随决策的隐私档位；服务不在线时自动退回**键盘剧本模式**（空格触发原时序），状态徽标如实标注当前模式。

## 操作

- 数字键 `1`—`4`：切换场景。
- 空格：在深夜跌倒场景启动演示流程。
- 右上角“全屏演示”：进入全屏。
- 首次打开需允许摄像头权限；姿态模型首次加载需要网络。

## 边界说明

- 跌倒流程双模式：接入 B 决策流时走真实链路（A 感知候选 + B 询问先行/超时升级，ADR-0005/0007）；脚本模式仅为服务离线兜底，两种模式界面均如实标注。真实链路仍不构成医学或安全级别的跌倒检测承诺。
- 真实模式启动方式：`uv run python -m reme.pose.runtime_server`（A，默认 8770）与 `uv run reme-decision-server --port 8100`（B），再打开本页切到场景四。
- 厨房人物抠图依赖 MediaPipe 分割掩码；若暂不可用，界面会明确显示“原画降级”。
- 摄像头或模型不可用时显示演示骨架，状态栏会标记当前数据源，不伪装成真实识别结果。
