# `.scratch` 协作与过程记录

`.scratch/` 保存仍需要审查和追溯、但不属于正式产品目录的工作资料。

适合放入：

- spec、issue、计划和验收记录；
- 团队角色交接与跨模块接口对齐；
- 实验结论、失败记录和人工 Gate；
- 理论笔记及直接复现笔记数字的辅助脚本；
- 项目整理、发布和审计记录。

不再放入：

- 已成为正式产品运行时的代码；
- 可独立运行、需要长期维护的实验目录；
- 大型模型、视频、训练数据或逐帧输出；
- API key、个人信息或可识别家庭材料。

目录迁移规则：

- 产品代码 → `backend/` 或 `frontend/`；
- 自包含实验 → `experiments/`；
- 通用脚本 → `scripts/`；
- 长期文档 → `docs/`；
- 模型与本地产物 → `models/` 约定位置或 Git 忽略的 `artifacts/`。

移动已有文件必须使用 `git mv`，并在同一批次更新引用路径。过程资料即使过时也不要直接删除；先在审计中标记，再由负责人确认归档或删除。
