## 1. 强制边界

只允许修改：

- `frontend/`
- 必要的前端使用说明
- 前端专项测试

禁止修改：

- `backend/`
- `models/`
- `data/`
- RuntimeEvent、HTTP、WebSocket 或 MiMo schema
- 姿态、跌倒阈值和决策策略
- GPU 严格模式：不得恢复 CPU 静默 fallback

若发现后端问题，只记录到 `.scratch/frontend-demo-polish/issues.md`，不要跨边界修复。

## 2. 优化重点

### 2.1 现场首屏

- 1920×1080 浏览器窗口中，老人端画面、家属手机与关键状态必须无需滚动即可看到；
- 不使用固定 `100vh` 导致浏览器工具栏或 macOS Dock 遮挡；
- 摄像头比例保持来源比例，不拉伸；
- 家属手机不遮挡主要画面和操作区；
- 验收控制可下移，但关键场景切换和风险动作保持可达。

### 2.2 状态可见性

页面必须清楚区分：

- 摄像头权限/连接状态；
- GPU 姿态模型加载状态；
- `inference_backend=gpu`；
- WebGL 渲染器；
- 统一后端在线状态；
- 当前输入模式 `landmarks`；
- 本地关键点、后端关键点和演示骨架来源；
- 降级原因。

不能用“ready”掩盖模型未加载或后端离线。

### 2.3 四场景表现

- 客厅：正常生活氛围，骨架清晰但不抢占主体；
- 厨房：分享询问、老人回复和家属提醒的因果顺序清楚；
- 浴室：默认只显示骨架，任何状态都不能误开原视频；
- 跌倒：候选、询问、超时、家属告警的状态变化要明显但不过度闪烁。

### 2.4 操作与路演

- 数字键 1–4 切场景稳定；
- 手动场景按钮有明确禁用、请求中和完成状态；
- 防止连续点击产生重复请求；
- Debug 面板默认不影响画面布局；
- `?debug=1` 可用于技术验收；
- 页面刷新后能自动重新连接，不需要手工清理状态。

### 2.5 性能

- 不增加新的大体积 UI 框架；
- 避免每帧 React state 更新；
- Canvas 绘制继续通过 ref/RAF；
- 检查摄像头、MediaPipe、WebSocket 和 animation frame 在卸载时释放；
- 典型场景页面连续切换 20 次不得出现重复摄像头流或重复 WebSocket。

## 3. 验收

必须通过：

```bash
cd frontend
npm test
npm run lint
npm run build
```

人工验收：

1. 1920×1080 首屏完整；
2. 摄像头比例正确；
3. GPU 状态可见；
4. 后端断开时显示真实降级原因；
5. 四场景切换无明显布局跳动；
6. 浴室场景永不显示原视频；
7. 连续切换 20 次后无重复摄像头和 WebSocket；
8. 不修改后端及模型文件。
