## 1. 角色目标

D 负责把 A、B、C 已经完成并可验证的能力，组织成评委能够在有限时间内理解、记住和信任的作品。

D 的最终责任不是单纯“做一套好看的 PPT”，而是完成四个闭环：

1. 产品定位闭环：为什么这个问题值得解决；
2. 比赛评分闭环：创新、技术、场景、体验、商业和完成度逐项有证据；
3. 演示叙事闭环：软件动作与讲解内容严格同步；
4. 答辩可信闭环：所有主张都能回到代码、日志、截图、测试或明确边界。

一句话职责：

> D 负责让评委准确理解 Reme 做了什么、为什么不同、48 小时内完成了什么，以及哪些能力仍处于实验阶段。

## 2. D 的职责边界

### 2.1 D 负责

- 产品名称、副标题和一句话定位；
- 用户问题、目标场景和用户旅程；
- 作品申报文案；
- 路演 PPT 和演讲稿；
- Demo 讲解顺序和节奏；
- 创新性、技术领先性、应用场景、用户体验、商业价值和完成度表达；
- 小米生态协同表达；
- 专利潜力与特殊社会价值说明；
- 评委问答和失败兜底话术；
- 页面截图、录屏和提交素材的选择与包装；
- 统一 A、B、C 对外使用的术语。

### 2.2 D 不负责

- 训练或修改 A 的姿态分类模型；
- 自行定义 B 的风险等级和主动交互逻辑；
- 重写 C 的软件页面或在比赛后期要求大改架构；
- 在没有测试数据时承诺准确率、误报率、延迟或医学效果；
- 把静态 `lying` 直接描述成可靠跌倒检测；
- 把候选功能、脚本功能或离线结果描述为实时已完成功能；
- 声称原始画面永远不会进入 MiMo。

## 3. 当前统一产品口径

### 3.1 作品名称

主名称：**Reme**

建议副标题：

> 基于姿态理解、视觉隐私判断与 MiMo 主动决策的老人关怀智能体

### 3.2 一句话定位

> Reme 从家庭视频中提取姿态和时序状态，并在需要时将结构化信息及最小视觉上下文交给 MiMo 判断是否介入、如何沟通，再把确认后的需要转成家属可以执行的行动。

### 3.3 核心记忆点

- **看懂**：通过骨架和时序变化理解动作事实；
- **克制**：日常不持续把清晰画面交给家属，不进行持续云端上传；
- **出现**：异常时主动询问、通知家属并分级升级。

### 3.4 隐私统一口径

根据 ADR-0003，团队允许经过明确触发的关键帧或短视频进入 MiMo。

对外必须准确说明：

- 原视频由本地感知链路持续处理；
- MiMo 可以接收当前判断所需的结构化事件和最小视觉上下文；
- 视觉发送不是持续后台直播，而是事件触发、最小采样、可观察的请求；
- 请求完成后，本地应用不额外留存临时视觉文件，除非开启明确的调试模式；
- 家属端默认接收事件、摘要、行动卡和骨架化展示，而不是持续清晰画面；
- 比赛版本不宣称已经解决生产环境中的长期存储、授权、加密和云端数据政策问题。

推荐表述：

> Reme 不是完全拒绝视觉信息，而是把视觉使用从“持续观看”改成“按需取证”：只有当前判断确实需要时，才发送最少的关键帧或短视频给 MiMo。

## 4. 比赛评分维度对应

### 4.1 作品创新性

必须讲清三个差异：

1. 不把姿态识别结果直接等同于告警；
2. 把视觉隐私状态和关怀状态放入同一决策链；
3. 使用“观察—询问—确认—通知—升级”的主动关怀流程。

证据来自：

- A 的静态姿态与时序转变分离；
- B 的结构化决策状态机；
- C 的隐私模式、主动询问和家属通知演示。

### 4.2 技术领先性

应展示：

- MoveNet 17 点关键点链路；
- 2D / 3D 骨架可视化；
- 静态姿态与时序转变分类；
- MiMo Structured / Visual 两种输入能力；
- 固定 JSON、Schema 校验和降级；
- `live / mock / record` 三种演示模式。

不得使用未经测量的“医疗级”“零误报”“完全实时”等词。

专利潜力可围绕：

- 姿态事件与视觉隐私状态的联合决策；
- 多阶段确认的主动关怀方法；
- 骨架代理展示与最小视觉上下文调用机制。

### 4.3 应用场景

主场景只聚焦老人家庭关怀：

- 独居老人；
- 白天独处老人；
- 异地家庭照护。

养老机构、康复训练和其他人群仅作为扩展，不进入主故事。

### 4.4 用户体验

老人端：

- 正常时不打扰；
- 异常时先询问；
- 可拒绝、可结束；
- 必要时才升级。

家属端：

- 不要求持续看监控；
- 收到结构化事件和系统已执行动作；
- 获得明确下一步建议；
- 能反馈“已确认”“误报”“已处理”。

### 4.5 商业价值

优先表达软件能力层，而非新硬件：

- 家庭版订阅；
- 养老与康复机构版；
- 向摄像头、音箱、电视、手机等设备提供 SDK / API；
- 与小米摄像头、音箱、手机、电视、手环和智能家居联动。

商业价值必须建立在“复用已有设备入口”和“提升现有设备关怀能力”上。

### 4.6 作品完成度

D 必须把内容划分为：

- **已完成且实测**；
- **已实现但仅离线或脚本模式**；
- **正在联调**；
- **未来规划**。

已完成内容必须附至少一种证据：

- 可运行页面；
- 结构化日志；
- 测试报告；
- 演示录屏；
- 代码路径；
- 截图。

## 5. PPT 结构

建议控制在 10–12 页。

| 页码 | 内容 | 证明点 |
|---|---|---|
| 1 | 作品名称与一句话定位 | 快速建立记忆 |
| 2 | 老人安全与隐私矛盾 | 真实问题 |
| 3 | Reme 整体闭环 | 完整方案 |
| 4 | 作品创新性 | 与普通监控/跌倒检测的差异 |
| 5 | 正常场景 Demo | 少打扰 |
| 6 | 视觉隐私与 MiMo 判断 | 按需视觉、非持续上传 |
| 7 | 异常主动关怀 Demo | 询问、确认、通知和升级 |
| 8 | 技术架构 | A/B/C 技术分层 |
| 9 | 用户旅程 | 老人端与家属端体验 |
| 10 | 商业与小米生态 | 落地路径 |
| 11 | 48 小时完成度 | 代码、日志、测试、录屏 |
| 12 | 特殊价值与结束语 | 尊严、普惠、可信 |

每页只保留一个核心结论，技术页不要堆砌模型名称。

## 6. Demo 与路演协作

### 6.1 与 C 的协作

C 提供：

- 可运行 Demo；
- 三个场景入口；
- 页面截图和录屏；
- 当前限制；
- `live / mock / record` 的切换方式。

D 负责：

- 固定现场操作顺序；
- 给每个页面状态配一句讲解；
- 控制切换时间；
- 让 PPT 和软件使用相同字段名称；
- 准备软件失败时的录屏切换话术。

### 6.2 与 A 的协作

A 提供：

- 已测关键点覆盖结果；
- 姿态分类指标；
- 混淆矩阵和拒判率；
- 已知失败场景；
- 2D / 3D 骨架素材。

D 不得引用论文指标作为 Reme 的实际指标。

### 6.3 与 B 的协作

B 提供：

- MiMo 输入输出示例；
- Structured / Visual 请求日志；
- Schema 校验与降级结果；
- 主动交互状态机；
- 老人端和家属端文本。

D 必须在演示中标明当前请求是否包含视觉上下文。

## 7. 路演结构

五分钟参考节奏：

| 时间 | 内容 |
|---|---|
| 0:00–0:35 | 用户故事与核心矛盾 |
| 0:35–1:05 | 作品定位与整体闭环 |
| 1:05–3:05 | 正常、视觉隐私、异常关怀三个场景 |
| 3:05–3:50 | 技术创新与 MiMo 作用 |
| 3:50–4:25 | 用户体验、商业和生态 |
| 4:25–4:45 | 48 小时完成度与测试证据 |
| 4:45–5:00 | 价值总结 |

开场问题建议：

> 当家庭为了安全安装摄像头时，能不能让系统在需要时理解画面，而不是让家属一直观看画面？

结束语建议：

> 真正的关怀，不是一直看着一个人，而是在需要时理解、确认并采取行动。

## 8. 评委问答

必须准备：

- 为什么不是普通跌倒检测？
- 为什么需要 MiMo？
- 正常躺下和跌倒如何区分？
- 哪些图片或视频会进入 MiMo？
- 为什么这仍然比持续云端监控更保护隐私？
- 临时视觉内容是否保存？
- 误报和无响应如何处理？
- 网络断开时怎么办？
- 48 小时内实际完成了什么？
- 当前准确率和限制是什么？
- 如何进入小米生态？
- 哪些方向具有专利申请潜力？

回答必须区分实测事实、候选设计和未来规划。

## 10. 验收标准

- [ ] 六项比赛评分维度均有明确页面和证据；
- [ ] PPT 与 A/B/C 实际能力一致；
- [ ] 隐私口径符合 ADR-0003；
- [ ] 没有“原始画面绝不进入 MiMo”的错误承诺；
- [ ] 没有未经测量的准确率、误报率和延迟；
- [ ] 主演示在规定时间内完成；
- [ ] Demo 失败时可在 10 秒内切换录屏或脚本模式；
- [ ] 所有成员使用相同的姿态、风险和演示模式术语；
- [ ] 评委能明确复述作品与普通摄像头的差异；
- [ ] 完成度页面能够区分已完成、联调中和规划项。

## 11. 当前最高优先级

1. 从 C 获取当前可运行 Demo 和三场景截图；
2. 从 A 获取已测事实与尚未通过的 Gate；
3. 从 B 获取视觉路径和结构化路径的真实请求示例；
4. 将远端规划文档中的旧隐私口径全部更新；
5. 完成 PPT 骨架和五分钟第一版逐字稿；
6. 根据最终联调结果删除未实现内容；
7. 完成至少三次完整彩排并记录超时点。
