# 在"没有多类别真实数据"条件下的验证协议

- 日期：2026-08-01
- 前置事实：见 [`data-reality.md`](data-reality.md)
- 适用对象：D（数据处理）为 A 任务构建的可解释生物力学姿态分类器

## 0 为什么需要这份协议

常规做法是"标注 → 训练 → 在留出集上报告 precision/recall/F1"。这条路在当前条件下**走不通**：

- 唯一的真实人体素材全程只有 `standing`；
- 覆盖 5 类的 `downloads6` 目录是动画素材 + 文件名推断标签 + 媒体不在本机；
- 因此 `sitting` / `lying` / `bending_or_crouching` **没有任何真实人体真值**。

在这种条件下仍然对外报告四类 F1，就是编造指标，违反 `AGENTS.md`
"Never invent accuracy, latency, supported-behaviour, or privacy claims"。

本协议给出的替代方案是**分层验证**：把"分类器是否正确实现了它声称的物理判据"
与"这些物理判据在真实老人场景里是否成立"**分开验证**，并且只对前者给出结论。

## 1 四层验证，各自能证明什么

| 层 | 验证对象 | 手段 | 能得出的结论 | **不能**得出的结论 |
|---|---|---|---|---|
| V1 几何正确性 | 特征计算是否等于其数学定义 | 解析构造的关键点 + 闭式期望值 | 代码实现无误 | 判据是否适合真人 |
| V2 判据行为 | 判据在受控姿态上的响应 | 正向运动学合成骨架，扫描角度 | 判据边界位置、单调性、拒判区 | 真实场景准确率 |
| V3 噪声鲁棒性 | 判据在实测噪声下的稳定性 | V2 骨架 + 实测 σ=1.3 px 高斯扰动，蒙特卡洛 | 置信度是否诚实、抖动幅度 | 真实遮挡/异常姿态表现 |
| V4 真实素材 | 在唯一真实片段上的表现 | 2370 帧真实数据 | **仅** `standing` 的稳定性/抖动/拒判率 | 其余任何类别 |

**对外可报告的只有 V1–V4 各自的结论，并且必须带上"不能得出"那一列。**

## 2 V1：几何正确性

对每个几何量，构造一组**闭式可验证**的输入：

- 躯干与竖直方向夹角：把肩中点放在髋中点正上方 → 期望 0°；
  绕髋中点旋转 θ → 期望 θ（在像素纵横比已还原的前提下）。
- 大腿段与水平夹角：髋、膝坐标直接构造，期望值由 `atan2` 闭式给出。
- 分段质量加权质心：用**单位质量集中在一点**的退化输入，期望质心等于该点；
  用两点等质量输入，期望质心在中点。
- 骨长比例：构造已知比例的骨架，期望比值等于构造值。

判据：数值误差 < 1e-9（纯几何，不涉及浮点病态）。
这一层**必须全绿**，它证明的是"代码算的就是文档写的"。

## 3 V2：判据行为（正向运动学合成）

### 3.1 合成器

写一个 2D 正向运动学骨架生成器：

输入：
- 各段与竖直方向的夹角（躯干、左右大腿、左右小腿、左右上臂、左右前臂、头颈）；
- 环节长度比例（来自人体测量学文献，**必须在代码里标注出处**）；
- 相机方位角 `azimuth`（用于模拟前缩：把矢状面内的坐标按 `cos(azimuth)` 压缩到图像 x 轴）；
- 整体平移与缩放（模拟人在画面中的位置与远近）。

输出：COCO-17 的 `x_norm / y_norm / score`，与 A 的记录形状一致。

**这个合成器的价值不在"造数据训练"，而在于它让每条判据的边界可被逐度扫描。**

### 3.2 扫描实验

对每个姿态类别，扫描其关键自由度并记录判据输出：

- `standing → bending`：躯干角从 0° 扫到 90°，步进 1°，记录标签翻转点与拒判带宽度；
- `standing → sitting`：大腿段从竖直扫到水平，记录翻转点；
- `sitting → lying`：躯干从竖直扫到水平，记录翻转点；
- `bending vs sitting` 混淆边界：同时扫躯干角与大腿角，输出二维决策图；
- 前缩：固定姿态，扫 `azimuth` 从 0°（正对矢状面）到 90°（正对冠状面），
  记录判据何时开始失效、拒判是否按预期触发。

判据：
1. 每个翻转点必须落在设计文档声明的阈值 ± 噪声带内；
2. 翻转点附近必须存在**非空的拒判带**（不允许硬翻转）；
3. 前缩扫描必须显示"随 azimuth 增大置信度单调下降"，并在设计声明的角度触发拒判。

二维决策图应当作为产物保存（文本矩阵即可，不需要图像），供人工核查与路演展示。

### 3.3 合成数据的边界（必须写进报告）

合成骨架是**由判据所使用的同一套几何假设生成的**，因此它**不能**证明判据适合真人：
它只能证明判据在自己的假设内自洽、边界位置符合声明、拒判带存在。
把 V2 的结果表述成"准确率"是错误的。

## 4 V3：噪声鲁棒性（蒙特卡洛）

用 `data-reality.md` 第 6 节实测的 σ ≈ 1.3 px（@1280×720，核心 8 点）：

- 对 V2 的每个合成姿态，加 N(0, σ²) 独立扰动，重复 1000 次；
- 统计：标签翻转率、置信度分布、拒判率；
- 关键检验：**声称的置信度是否与实际正确率一致**（可靠性/校准曲线）。
  若判据在某姿态输出 0.9 置信度，但蒙特卡洛显示 30% 的扰动样本翻转标签，
  则该置信度是**虚高的**，必须修正映射函数。

还应扫描 σ 的倍数（1×、2×、5×）以模拟更差的提取质量，
并验证段长低于 21 px 时角度证据确实被降权或拒判（对应实测的 5° 1-σ 门槛）。

## 5 V4：真实素材（唯一的真实人体证据）

在 `.scratch/posture-classifier-theory/data/movenet17-real-2370.jsonl`（2370 帧）上运行，报告：

| 指标 | 期望 | 理由 |
|---|---|---|
| `standing` 占比 | 高且稳定 | 实测躯干角 max 13.7°、大腿角 min 73.7°、髋<膝<踝 100% 成立 |
| 标签抖动次数 | 尽可能少 | 79 秒内人始终站立，任何标签变化都是误判或拒判 |
| 拒判率 | 记录实际值 | 该片段受试者接近侧向（肩宽/躯干 = 0.12），前缩门控可能触发拒判——**这是正确行为，不是缺陷** |
| 每帧耗时 | 记录实际值 | 需支撑 5–10 Hz 输出 |

**预期张力**：前缩门控越严格，这段侧向素材被拒判得越多。
这不是 bug，而是设计诚实性的体现；报告必须同时给出拒判率与拒判原因分布，
让评审能看到"分类器知道自己在什么条件下不可信"。

**禁止**：不得为了让这段视频"好看"而放松前缩门控。阈值必须先由理论与噪声分析定下，
再看这段视频的结果，而不是反过来。

## 6 报告模板（防止过度声明）

最终报告必须逐字包含以下结构：

```text
已验证：
- 几何实现正确性（V1）：<结果>
- 判据边界与拒判带（V2，合成）：<结果>
- 噪声下的置信度校准（V3，蒙特卡洛，σ=1.3px 实测）：<结果>
- 真实素材上的 standing 稳定性（V4，2370 帧）：<结果>

未验证（当前无数据）：
- sitting / lying / bending_or_crouching 在真实人体上的 precision / recall / F1
- 跨人物、跨机位、跨光照泛化
- 老年人体态（脊柱后凸、身高丢失）下的适用性
- 任何跌倒式转变的检测能力

阈值来源：
- <逐条列出：文献先验 / 噪声分析推导 / 待校准>
```

## 7 解除限制所需的最小补拍

要把"未验证"清单中的任何一项转成"已验证"，需要的**最小**真实素材：

- 每个目标类别 ≥ 3 个不同人物、≥ 2 个机位角度的连续片段；
- 每段包含进入该姿态的完整过程与稳定保持段（便于同时支撑静态与时序标注）；
- 至少一段刻意的正常躺下与一段受控的跌倒式转变（安全前提下用软垫，或明确标注为脚本触发而非模型识别）；
- 按人物划分 train/val/test，禁止相邻帧随机打散；
- 拍摄时同步记录机位高度、俯仰角与人物朝向，用于验证前缩模型。

在补拍完成前，任何四类指标都不应出现在 PPT、答辩材料或对外文档中。
