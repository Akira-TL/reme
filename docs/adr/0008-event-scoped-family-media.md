# ADR-0008: 事件级家属媒体通道与三平面演示

- Status: Accepted for LBX demo feasibility
- Date: 2026-08-02
- Owner: C（跨设备演示）
- Depends on: ADR-0003、ADR-0005、ADR-0007

## 背景

现有公网双端只同步 MoveNet 17 点骨架。它证明了“一台监控手机、多个只读评委”可以共享同一隐私化状态，但还不能真实演示四个产品场景：日常空间、做饭心跳、完全隐私、跌倒升级后查看现场。

主分支的单机路径已经给出可复用的场景视觉和问询交互，但把家中画面直接画在同页家属手机上并不构成跨设备传输；厨房进入场景即显示原画、跌倒在 `checking` 阶段显示原画，也早于既有授权边界。

## 决议

LBX 的跨设备演示拆成三个互不替代的数据平面：

1. **姿态平面**：沿用严格的 `movenet-17/v1-demo` 合同，只广播 17 点骨架；未知字段、二进制和媒体字段继续拒绝。
2. **事件平面**：广播版本化场景状态、活动候选、家庭心跳卡和告警状态。它只含结构化文本与枚举，不承载媒体。
3. **事件媒体平面**：媒体不经过骨架 Relay，也不写入 Durable Object。控制端与已经在场的评委端仅在一个短期 `media_grant` 下通过 WebRTC 传输。

媒体授权遵守以下不变量：

- 厨房画面必须在活动被真实识别后，再由本人明确同意；未同意、拒绝或超时均不得签发媒体授权。
- 跌倒候选与本地问询阶段仍只显示骨架和环境抽象；只有确定性规则进入 `family_notification_required` / `urgent_attention`，或 ADR-0007 的危险确认已经产生同等级告警后，才签发 `fall_emergency` 授权。
- `media_grant` 绑定 `session_id / event_id / scope / audience / expires_at_ms / grant_id`，只授权签发时已经连接的 viewer WebSocket。新加入的旁观者不继承正在进行的原画授权。
- 授权到期、场景切换、事件解决、控制租约释放或控制端断线时，前端必须停止全部媒体轨道并撤销授权。
- WebRTC 信令可经 Durable Object 转发；SDP/ICE 不是媒体。DO 不接收视频帧、音频帧、Base64 图片或录像 Blob。
- 该能力是单房间路演授权，不是生产账户系统。正式产品需要独立的身份、审计、撤销、TURN/SFU 和保留策略 ADR。

## 场景视觉决议

- 日常和跌倒前使用“通用火柴人/骨架 + 固定虚拟家具背景”。这是一种场景抽象，不宣称从真实家庭画面重建家具。
- 完全隐私场景只显示骨架与纯色安全背景，忽略任何上游 `video` 或环境模式。
- 不使用实时人像抠图或模糊垫底。当前模型没有经验证的分割掩码，抠图边缘、漏像素和闪烁既会降低演示质量，也会产生可识别像素泄漏。
- 原画出现时必须有明确的授权原因、剩余时长和关闭状态；失败时回落到骨架并显示降级，不保留最后一帧冒充直播。

## 做饭识别边界

厨房识别是独立可行性 Gate，不从“切换到厨房场景”推断活动。控制端最多周期性选取一张降采样 JPEG，显式调用 MiMo 视觉分类；返回 `cooking / not_cooking / uncertain`、置信度与一句依据。连续两个达到阈值的 `cooking` 结果才形成活动事件。

被发送的最小图片、调用时间和模型结果必须在控制端可见；失败或密钥未配置时展示 `unavailable`，不得脚本伪造“正在做饭”。短时刻可在控制端内存中录制，拒绝、超时或 TTL 到期即释放；本 ADR 不允许把录像写进 DO、KV 或仓库。

## 跌倒识别边界

浏览器侧可用可测试的确定性几何/时序规则从真实姿态流产生 `fall_like_transition` 候选；这仍是未经临床验证的演示启发式。问询与超时升级必须遵守 ADR-0005，MiMo 或媒体连接失败不能延迟规则告警。

## 后果

- 评委端可以先看到隐私化场景，再在厨房同意或跌倒告警后看到短期真实现场。
- 主分支的视觉结构可继续复用，但其同页 Canvas 原画不能作为跨设备媒体实现。
- Relay 的媒体拒绝测试继续有效；新增事件和信令必须走各自精确合同与独立测试。
- 如果目标手机、跨网络 ICE、做饭识别或跌倒启发式 Gate 未通过，相关能力必须显式显示降级，路演仍可回到纯骨架路径。
