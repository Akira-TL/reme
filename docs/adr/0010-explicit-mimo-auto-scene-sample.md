# ADR-0010: 显式单样本 MiMo 场景提议

- Status: Accepted for LBX demo feasibility
- Capability gate: Pending real-device measurement
- Date: 2026-08-02
- Owner: C（LBX 公网共享 Demo）
- Depends on: ADR-0003、ADR-0005、ADR-0008

## 背景

LBX 已有四个手动场景按钮，并在评委端按 `living / kitchen / bathroom / fall` 渲染四种隐私展示。
用户希望在四个场景之外增加一个“打开真实识别”的动作，让 MiMo 查看当前真实摄像头样本并自主提出
当前场景，再切换到已有展示模式。

现有证据证明 MiMo API 接受 Base64 图片和 MP4 `video_url`，但没有目标手机真实四场景分类证据。
持续后台视频上传还会违反 ADR-0003 的显式、最小、可观察边界，并让完全隐私、成本和失败状态变得不可审计。
MiMo 也不能成为 ADR-0005 确定性跌倒升级链的承重墙。

## 决议

接受一个独立的第五**动作**“真实识别 · MiMo”，不增加第五场景。动作遵循“一次点击、一个最小样本、
一个提议”的合同：

1. 默认在监控端内存中录制约 2 秒 MP4，并通过当前控制租约鉴权的 Relay HTTP 端点调用 MiMo。
2. 浏览器不支持 MP4 MediaRecorder、录制失败或没有有效 MP4 时，只发送一张降采样 JPEG；UI 必须在发送时
   明确标识 `JPEG fallback`。一次点击不允许先后发送两种媒体。
3. MiMo 只返回 `living | kitchen | bathroom | fall | uncertain`、未校准 `confidence` 和可观察依据。
4. 通过精确合同和本地接受策略的提议只切换现有 `scene_state`。`uncertain`、低置信、非法、超时或迟到结果
   保留当前模式并显示降级。
5. 四个手动场景按钮永久保留为显式 fallback；人工选择优先于在途提议，迟到结果不得覆盖人工状态。
6. 不设置定时器、场景监听器或后台循环采样。每次重新判断，包括处于 `bathroom` 完全隐私模式时，都必须由
   操作者再次明确点击该动作。
7. 原始 MP4/JPEG 只存在于本轮请求的内存生命周期，不写入浏览器持久存储、日志正文、事件平面、DO、KV
   或仓库。DO 不接触视觉正文；只允许 Relay 请求处理路径把当前样本转给 MiMo。
8. 浏览器不得直连 MiMo 或持有 API key。Relay 必须验证活跃控制租约、媒体类型/魔数/硬上限、精确模型输出、
   超时和脱敏审计字段。

## 场景与安全不变量

- `living` 只切换日常展示。
- `kitchen` 只切换做饭场景展示；它不等于人物正在做饭，不创建家庭心跳，不代表本人同意记录或分享。
- `bathroom` 立即使用既有 skeleton-only fail-closed 展示；只有新一次明确点击才允许再向 MiMo 发送样本。
- `fall` 只切换跌倒展示/候选叙事。它不能创建、升级、解除或延迟告警，不能暂停规则倒计时，不能直接签发
  `fall_emergency` 媒体授权，也不能启用本地 MoveNet 跌倒时序规则；只有人工点击“跌倒”场景才启用该规则。
- 已有问询或告警的风险状态不因任何 MiMo 场景结果降低、隐藏或结束。
- 切到厨房或其他场景不得从该第五动作级联出第二个未披露视觉请求。厨房 `cooking` 识别是独立 Gate，
  需要独立触发、披露和证据，不能把场景提议当成活动识别。

完全隐私的可辩护口径因此是：评委端始终只看骨架、没有后台视觉上传；操作者主动点击“真实识别 · MiMo”时，
会显式发送一次最小样本。只要允许该点击，就不得宣称“完全隐私时任何云端从未看到像素”。

## Gate 状态

本 ADR 接受的是**实验边界**，不是能力结论。以下仍为 pending：

- 目标手机真实 MP4 与 JPEG fallback 是否都可用；
- 四类真实素材、困难负例和场景切换上的质量与拒判；
- 同一输入重复调用的稳定性；
- 端到端时延、请求大小、MiMo usage 与实际成本；
- 断网、拒权、取消、会话变化和迟到响应的失败可见性。

Pilot 必须先冻结提示词、模型参数、接受阈值和评估素材，再用未参与调参的 Holdout 作 go/no-go。
当前不得编造准确率、误报率、时延或费用，也不得把已有合成媒体 HTTP 200 当作能力通过。
LBX 线束可用 `0.65` 作为明确标注的未校准起始 guardrail，以便测试接受与拒绝分支；它不构成已接受阈值，
必须在 Pilot 后重新评审并在 Holdout 前冻结。

## 不接受的替代

- **第五场景按钮**：拒绝。MiMo 是识别动作，不是新的产品场景。
- **持续/周期性上传视频或关键帧**：拒绝。违反显式单样本、最小化和完全隐私模式的可观察边界。
- **MP4 失败后静默追加 JPEG**：拒绝。一次点击会变成两次视觉暴露；fallback 必须发生在首个请求之前并可见。
- **浏览器直连 MiMo**：拒绝。会暴露 API key，并绕过租约、大小、超时、预算和审计控制。
- **强制四选一**：拒绝。`uncertain` 和低置信必须保留当前模式。
- **MiMo `fall` 直接报警或解警**：拒绝。违反 ADR-0005 的确定性升级和 no-model-cancellation 不变量。
- **自动场景结果触发厨房记录/分享**：拒绝。场景、活动、本人同意和媒体授权是四个不同事实。

## 后果

- 路演可在保留四个手动 fallback 的同时，增加一次可观察、可审计的真实 MiMo 场景提议。
- MP4 和 JPEG 路径必须分别记录，不能把 fallback 隐藏在一个笼统“视频识别成功”口径中。
- 自动场景路径只需写入既有展示场景，不需要扩展告警状态机或媒体授权合同。
- 自动场景请求期间暂停并取消既有厨房活动视觉请求；自动切到厨房、或从存储恢复厨房展示，都不会自行启动
  `cooking` 采样，必须再次人工点击“做饭”。既有 `scene_state` 仍是来源中性的投影状态，提议来源与接受结果
  只在控制端状态卡和 Relay 脱敏元数据中可见；Gate 通过前不扩展永久事件 Schema。
- 浏览器取消自动场景或既有厨房请求时，Relay 必须把入站 `request.signal` 继续传播到 MiMo 上游，避免页面
  已经取消但旧视觉请求仍继续占用单次预算或与新场景请求重叠。
- 需要新增窄实验端点、严格模型输出解析、取消/迟到保护和目标手机 Gate；在 Gate 通过前，生产能力仍视为不可用。
- 如果真实 Gate 不通过，四个手动按钮继续构成完整演示 fallback，且不得把 MiMo 提议包装成已验收的自动能力。
