# Reme ABC 单机快速启动

## 推荐方式

在仓库根目录执行：

```bash
uv run reme-local-demo
```

也可以执行：

```bash
scripts/start-demo.sh
```

macOS 可双击根目录的 `启动Reme全链路演示.command`。三个入口最终都调用同一个 Python 启动器，不存在两套不同的进程管理逻辑。

启动器会：

1. 检查 8770、8100、4174 是否已有真实监听器。
2. 自动读取 `~/.config/reme/mimo.env`。
3. 缺少前端依赖时执行 `npm install`。
4. 启动 A 感知、B 决策和 C Vite。
5. 等待三个 HTTP 服务就绪。
6. 输出唯一验收地址。
7. 在 `Ctrl+C` 时按进程组统一停止三个服务，并明确输出 `[C] stopped`、`[B] stopped`、`[A] stopped`。

不使用 systemd，前端不由 B 静态托管。

## 验收地址

```text
http://127.0.0.1:4174/typical-demo.html
```

页面默认进入深夜跌倒验收场景。左侧为老人端现场视频与 A 返回骨架；右侧为家属手机端，默认只显示骨架。家属主动点击且不在浴室隐私场景时，才显示原视频与骨架叠加。

页面中部的“对话、沟通与提醒验收”工具栏提供真实链路测试：

- 厨房场景进入约 3 秒后，B 自动调用 `mimo-v2.5`，明确告诉模型当前看到奶奶在包包子，并要求先询问是否分享给孩子；
- `分享给孩子`：向 B 提交授权，随后家属手机收到普通生活提醒，不触发响铃、振动或紧急告警；
- `这次不分享`：B 关闭本轮对话，家属端不会出现生活提醒；
- `手动触发 MiMo 主动询问`：在客厅等现场场景手动代替真实触发条件，由 B/MiMo 主动提问并等待老人回复；
- `手动触发跌倒报警`：C 经现有 WebSocket 向 A 发送调试场景，B 依次产生安全询问和家属告警；
- `重播 MiMo 询问`：优先播放 B 返回的预置语音，失败时使用浏览器中文 TTS；
- `语音回复`：浏览器中文语音识别后，将安全、求助或分享授权提交给 B 的真实回应接口；
- 页面按钮可提交“我没事”“我需要帮助”“分享给孩子”“这次不分享”。

页面左下角有 `Debug` 按钮，可查看 A 的 session、输入模式、帧龄、人物检测、姿态分类来源、MIL v3 分数，以及 B 的 MiMo 配置、决策状态、语音识别文本和原始 JSON。`会话运行中` 只表示 A 会话已启动；`当前活动` 才表示是否收到新帧、是否检测到完整人体。需要打开页面时直接展开，可访问：

```text
http://127.0.0.1:4174/typical-demo.html?debug=1
```

## MiMo 配置

首次使用可执行：

```bash
scripts/setup-mimo-env.sh
```

也可以手动创建：

```bash
mkdir -p ~/.config/reme
printf '%s\n' 'export MIMO_API_KEY=你的key' > ~/.config/reme/mimo.env
chmod 600 ~/.config/reme/mimo.env
```

当前默认文本模型为 `mimo-v2.5`。没有 MiMo key 时，确定性跌倒询问、倒计时和家属告警仍可运行；厨房分享询问和现场主动关怀会使用 B 的固定安全话术或明确降级。

## 手动三终端方式

仅用于排障。正常验收优先使用一键命令。

A：

```bash
uv run python -m reme.pose.runtime_server \
  --host 127.0.0.1 \
  --port 8770 \
  --input-adapter c_ws_server \
  --browser-input-mode auto
```

B：

```bash
source ~/.config/reme/mimo.env 2>/dev/null || true
uv run reme-decision-server \
  --host 127.0.0.1 \
  --port 8100 \
  --a-events-url ws://127.0.0.1:8770/ws/events
```

C：

```bash
cd frontend
npm run dev -- --host 127.0.0.1 --port 4174 --strictPort
```

## 本地模型资产

MediaPipe wasm 会在 `npm run dev` 和 `npm run build` 前，从 `node_modules` 复制到 `frontend/public/mediapipe/wasm/`。姿态模型位于：

```text
frontend/public/mediapipe/pose_landmarker_lite.task
```

因此页面不再依赖运行时 CDN。模型或 wasm 加载超过 15 秒会显示明确降级，不会一直停留在“连接中”。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示端口已占用 | 8770、8100 或 4174 上存在真实监听器；先关闭旧进程后重试。 |
| 页面无法访问 | 观察启动命令中 `[A]`、`[B]`、`[C]` 前缀日志，确认三个服务都已就绪。 |
| 页面显示等待 ABC 链路 | 打开左下角 `Debug`，查看 A/B 的具体错误；再确认 B 健康状态中的 `attached` 和 `connected` 为 `true`。 |
| A 一直是 `starting` | 浏览器尚未获得摄像头权限，或还未发送第一帧。 |
| 摄像头没有画面 | 在浏览器和系统隐私设置中允许摄像头权限。 |
| 有画面但无骨架 | 先确认人物全身进入画面。当前 MoveNet 单人模型要求肩、髋、膝、踝尽量完整可见；半身取景会在姿态分类前被判为关键点不可用。再查看 Debug 中的 `A 检测到人物`、`A 关键点质量` 和 `当前活动`。 |
| Debug 一直显示会话运行中 | `会话运行中` 只是进程/会话状态，不代表识别到动作。查看 `当前活动`、`帧龄`、`A 检测到人物` 和姿态分类。 |
| 需要测试报警但不方便摔倒 | 使用页面的 `手动触发跌倒报警`；它通过真实 C→A→B 链路触发，不需要真人执行危险动作。 |
| 没有 MiMo 决策 | 在 Debug 中检查 `决策来源`；再检查 `~/.config/reme/mimo.env`。规则决策仍应正常工作。 |
| `Ctrl+C` 后页面仍能访问 | 正常退出应看到三个 `stopped`；若没有，说明启动器不是以前台方式运行。请先关闭后台启动方式，再直接执行 `uv run reme-local-demo`。 |

## 端口

| 组件 | 地址 | 用途 |
|---|---|---|
| A | `127.0.0.1:8770` | 浏览器输入、姿态和动作转变事件 |
| B | `127.0.0.1:8100` | A 事件订阅、规则/MiMo 决策、危险确认 |
| C | `127.0.0.1:4174` | Vite 验收页面 |
