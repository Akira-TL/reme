# Reme ABC 单机快速启动

## 1. 准备环境

在仓库根目录执行：

```bash
uv sync --extra dev --extra pose
```

MiMo 密钥保存在仓库根目录 `.env`，不会从 Home 目录读取。

推荐使用配置脚本：

```bash
scripts/setup/setup-mimo-env.sh
```

也可以手动配置：

```bash
cp .env.example .env
# 编辑 .env，填写 MIMO_API_KEY
chmod 600 .env
```

`.env` 已被 Git 忽略，不要提交真实密钥。

## 2. 启动完整 ABC 演示

推荐入口：

```bash
scripts/demo/start-local-demo.sh
```

等价入口：

```bash
uv run reme-local-demo
scripts/start-demo.sh
```

macOS 可双击根目录的 `启动Reme全链路演示.command`。这些入口最终都调用同一个 Python 进程管理器。

启动器会：

1. 检查 8770、8100、4174 端口。
2. 读取仓库根目录 `.env`。
3. 检查前端原生依赖；缺失或跨平台不兼容时执行 `npm ci`。
4. 启动 A 感知服务、B 决策服务和 C Vite 页面。
5. 等待三个服务就绪。
6. 在 `Ctrl+C` 时按进程组停止所有子进程。

验收地址：

```text
http://127.0.0.1:4174/typical-demo.html
```

调试信息默认展开：

```text
http://127.0.0.1:4174/typical-demo.html?debug=1
```

## 3. 组件和端口

| 组件 | 地址 | 入口 | 用途 |
|---|---|---|---|
| A | `127.0.0.1:8770` | `reme.pose.runtime_server` | 浏览器输入、姿态和动作转变事件 |
| B | `127.0.0.1:8100` | `reme.decision.server` | 规则/MiMo 决策、回应与危险确认 |
| C | `127.0.0.1:4174` | Vite | 四场景单机演示页面 |

主要数据流：

```text
C /ws/camera-input → A /ws/events → B /ws → C
```

## 4. 单独启动前端

只查看前端、不启动 A/B：

```bash
scripts/demo/start-frontend-preview.sh typical-demo.html
```

产品手机页：

```bash
scripts/demo/start-frontend-preview.sh index.html
```

兼容入口：

- `frontend/启动Reme典型场景演示.command`
- `frontend/启动Reme手机演示.command`

这些文件仅转发到 `scripts/launchers/macos/`。

## 5. 手动三终端排障

正常演示优先使用一键启动器。只有排查单个组件时才使用以下命令。

A：

```bash
uv run python -m reme.pose.runtime_server \
  --host 127.0.0.1 \
  --port 8770 \
  --input-adapter c_ws_server \
  --browser-input-mode auto
```

B：

```bash
set -a
source .env 2>/dev/null || true
set +a
uv run reme-decision-server \
  --host 127.0.0.1 \
  --port 8100 \
  --a-events-url ws://127.0.0.1:8770/ws/events
```

C：

```bash
cd frontend
npm run dev -- --host 127.0.0.1 --port 4174 --strictPort
```

## 6. 演示交互

`typical-demo.html` 包含客厅、厨房、浴室和跌倒场景。页面可查看：

- A 的 session、输入模式、帧龄、人物检测和姿态来源；
- B 的连接状态、规则/MiMo 决策和原始事件；
- 老人端和家属端的隐私视图；
- 安全回应、求助、厨房分享授权和手动跌倒调试入口。

`会话运行中` 只表示进程和 session 已启动，不代表已经检测到人物或动作。判断实时输入应查看帧龄、人物检测和关键点质量。

## 8. 常见问题

| 现象 | 检查方式 |
|---|---|
| 端口已占用 | 关闭旧的 A/B/Vite 进程后重试。 |
| 页面无法访问 | 查看 `[A]`、`[B]`、`[C]` 前缀日志，确认三个服务均已就绪。 |
| A 一直处于 `starting` | 确认浏览器摄像头权限以及是否已发送第一帧。 |
| 有画面但没有骨架 | 让人物全身进入画面，并查看人物检测、关键点质量和帧龄。 |
| 没有 MiMo 决策 | 检查根目录 `.env` 是否包含 `MIMO_API_KEY`；规则降级仍应可见。 |
| 前端依赖报原生模块错误 | 删除复制来的 `frontend/node_modules`，重新执行 `npm --prefix frontend ci`。 |
| 缺少训练模型 | 检查本机 `artifacts/pose-classification/`；模型未进入 Git 不代表未训练。 |
| `Ctrl+C` 后仍能访问页面 | 确认使用前台一键启动器，而不是手工留在后台的 Vite 进程。 |
