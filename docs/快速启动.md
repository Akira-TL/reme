# Reme 固定公开双端演示快速启动

## 1. 准备环境

环境要求：Python 3.11+、`uv`、Node.js 和 npm。在仓库根目录执行：

```bash
uv sync --extra dev --extra pose
cp .env.example .env
chmod 600 .env
```

项目默认只从仓库根目录 `.env` 读取项目配置，不使用 `~/.config`，也没有 `frontend/.env`。如需真实 MiMo 调用，可编辑 `MIMO_API_KEY`，或执行会进行一次真实 API 冒烟的：

```bash
scripts/setup/setup-mimo-env.sh
```

没有 MiMo key 时仍可运行确定性路径，但页面必须显示真实降级状态。不要提交 `.env`，也不要把 MiMo、TURN、Cloudflare 或其他 secret 写进会进入浏览器 bundle 的 `VITE_*`。

## 2. 桌面 loopback 启动

正式入口：

```bash
scripts/demo/start-local-demo.sh
```

它最终执行：

```bash
uv run --extra pose python -m reme.runtime.launcher
```

项目不定义 `[project.scripts]`，不会在 `.venv/bin` 安装 `reme-*` 命令。macOS 也可双击根目录的 `启动Reme全链路演示.command`。

启动器会：

1. 检查后端 `8770`、Vite `4174` 和 Relay `8787`；
2. 读取根 `.env`，检查前端和 Relay 依赖；
3. 启动本地统一后端；
4. 启动固定 `shared-live-demo` Worker/SQLite Durable Object Relay；
5. 启动包含 Monitor 与 Viewer 两个入口的 Vite；
6. 等待三个服务健康；
7. 在 `Ctrl+C`、`SIGTERM` 或 `SIGHUP` 时停止全部子进程组。

桌面入口：

```text
Monitor: http://127.0.0.1:4174/
Viewer:  http://127.0.0.1:4174/viewer.html
Debug:   http://127.0.0.1:4174/?debug=1
```

Chrome 把 loopback HTTP 视为安全上下文；这不代表手机访问 LAN HTTP 也能使用媒体权限。

## 3. 手机 LAN HTTPS

手机 Monitor 需要 `getUserMedia`，因此必须使用手机系统已经信任的 HTTPS 证书。证书 SAN 必须包含实际访问的 LAN IPv4 或 hostname；私钥不得提交。

假设电脑 LAN 地址为 `192.168.1.42`：

```bash
scripts/demo/start-local-demo.sh \
  --host 0.0.0.0 \
  --public-host 192.168.1.42 \
  --tls-cert /absolute/path/to/reme-lan-cert.pem \
  --tls-key /absolute/path/to/reme-lan-key.pem
```

手机访问：

```text
Monitor: https://192.168.1.42:4174/
Viewer:  https://192.168.1.42:4174/viewer.html
```

检查清单：

- 手机和电脑位于同一可信/隔离局域网；
- 手机已安装并信任签发证书的 CA；
- SAN 与地址或 hostname 完全匹配；
- 页面没有证书警告，浏览器报告 secure context；
- 浏览器和操作系统已授予摄像头/麦克风权限；
- 防火墙允许所需本地连接。

仅点击浏览器“继续访问”未受信任证书，不算完成证书信任或手机媒体验收。`--public-host` 必须和 `--host 0.0.0.0` 一起使用；当前启动器拒绝 IPv6。

Vite 把浏览器的 HTTPS/WSS 请求同源代理到 `/_reme/runtime/*` 与 `/_reme/relay/*`，避免页面回连不安全的 HTTP/WS。启动器目前会把三个服务绑定到指定 host，因此 wildcard 模式应只在可信网络短时使用。

## 4. 固定公开房间风险

`shared-live-demo` 故意没有密码和身份认证，只是比赛路演例外：

- 同一网络中能访问服务的人可作为 Viewer 加入；
- producer 空闲时，其他设备可尝试 claim Monitor；
- 最多 5 名 Viewer；同一时刻只有一个 30 秒可续租 controller；
- 演示结束必须关闭启动器，不应长期暴露端口。

这个实现不是生产访问控制、互联网公开房间或已证明合规的隐私方案。不要在不可信 Wi-Fi、公网端口映射或包含真实敏感影像的环境中运行。

## 5. 三进程结构

| 进程 | 默认监听 | 浏览器入口 | 用途 |
|---|---:|---|---|
| 统一后端 | `127.0.0.1:8770` | `/_reme/runtime/*` | JPEG 输入、MoveNet 17 点、姿态、连续转变、规则/MiMo 决策 |
| Relay | `127.0.0.1:8787` | `/_reme/relay/*` | 固定房间、状态、骨架、控制租约、ACK 和 WebRTC 信令 |
| Vite | `127.0.0.1:4174` | `/`、`/viewer.html` | Monitor、Viewer、HTTPS 终止和同源代理 |

后端内部数据流：

```text
Monitor JPEG /ws/camera-input
  → perception
  → 进程内 EventBroker / EventIngest
  → decision / MiMo
  → Monitor 状态与 17 点骨架
  → Relay
  → Viewer
```

原始 JPEG、Blob、data URL 和视频正文禁止进入 Relay JSON 或 SQLite。事件期原画使用 WebRTC RTP 直连，不经过 Worker。

## 6. 媒体与隐私门

Monitor 页面加载时不会主动弹系统权限框。点击“开始演示”取得 producer lease 后，摄像头、前后镜头、屏幕和文件仍必须在 Monitor 设备上由真实用户确认。

- 客厅：默认只同步骨架；
- 厨房：当前事件明确授权后，原画最多开放 60 秒；
- 浴室：任何命令、重连和迟到消息都不能开放原画；
- 跌倒：只有当前权威紧急升级后，原画最多开放 30 秒。

厨房和跌倒 grant 都面向全部在线 Viewer；晚到 Viewer 可以在剩余授权期加入。Viewer 的高隐私开关只能隐藏已经授权的原画，不能开启原画。

本地 Relay 不提供 TURN 凭证服务。无 TURN 时只承诺显示“本机/局域网能力”；跨 NAT、蜂窝网、访客隔离 Wi-Fi 或严格防火墙下的原画可能无法建立。STUN 不是 TURN，公网能力属于后续单独部署阶段。

## 7. 根 `.env` 与同源代理

根 `.env.example` 中的公开默认值适合单独开发：

```text
VITE_REME_PERCEPTION_HTTP_URL=http://127.0.0.1:8770
VITE_REME_PERCEPTION_INPUT_WS_URL=ws://127.0.0.1:8770/ws/camera-input
VITE_REME_DECISION_HTTP_URL=http://127.0.0.1:8770
VITE_REME_RELAY_URL=http://127.0.0.1:8787
```

完整启动器会依据 `--host`、`--public-host`、端口和 TLS 参数覆盖这些浏览器地址，统一改为 Vite origin 下的 `/_reme/runtime` 与 `/_reme/relay/`。这属于公开拓扑信息，不包含 secret。

## 8. 单独排障

只启动前端：

```bash
scripts/demo/start-frontend-preview.sh
```

该命令不启动后端或 Relay；缺失服务应在 UI 中显示不可用。

只启动统一后端：

```bash
uv run --extra pose python -m reme.runtime.server \
  --host 127.0.0.1 \
  --port 8770 \
  --input-adapter c_ws_server \
  --browser-input-mode jpeg
```

只启动 Relay：

```bash
npm --prefix demo-relay run dev -- --ip 127.0.0.1 --port 8787
```

## 9. 模型资产

运行时默认位置：

```text
models/runtime/movenet/movenet_lightning_f16_v4.tflite
models/trained/posture/posture-sweep-20260801/seed-42-lr-0.04/model.json
models/trained/fall/mil-v3/model.json
```

`models/trained/*` 是本机 ignored 资产，不得提交。模型缺失或外部训练样本缺失时必须显示并记录真实降级/skip，不能据此宣称准确率、帧率 Gate 或医疗能力。

## 10. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 手机页面可开但没有摄像头 API | LAN HTTP 不是安全上下文；改用证书受信任且 SAN 匹配的 HTTPS。 |
| HTTPS 页面仍提示不安全 | CA 未被手机信任、SAN 不匹配或证书过期；不能用警告页绕过代替修复。 |
| Monitor claim 返回 busy | 另一 producer lease 尚有效；关闭旧 Monitor，等待租约释放/到期后重试。 |
| Viewer 无法连接 | 检查 `[RELAY]` 日志、`/_reme/relay/health` 和固定房间状态。 |
| 有骨架但没有原画 | 日常/浴室本就禁止；事件 grant、媒体可远传性或无 TURN 网络也可能阻止原画。 |
| 页面显示等待运行时 | 查看 Debug，并检查 `[BACKEND]`、同源 runtime health 和当前 session。 |
| 有画面但无骨架 | 让人物全身进入画面，检查模型加载、人物检测、帧龄和关键点质量。 |
| 没有 MiMo 决策 | 检查根 `.env`；确定性规则应继续工作并显示降级来源。 |
| 退出后端口仍在 | 正常退出应依次看到 `[FRONTEND]`、`[RELAY]`、`[BACKEND] stopped`；保留日志排查遗留进程。 |

当前自动验证、缺失数据和真机待验清单见 [.scratch/public-dual-device-demo/validation.md](../.scratch/public-dual-device-demo/validation.md)。
