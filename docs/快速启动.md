# Reme 单机快速启动

## 1. 准备环境

在仓库根目录执行：

```bash
uv sync --extra dev --extra pose
```

MiMo 密钥保存在仓库根目录 `.env`，不会从 Home 目录读取：

```bash
scripts/setup/setup-mimo-env.sh
```

也可以手动配置：

```bash
cp .env.example .env
# 编辑 .env，填写 MIMO_API_KEY
chmod 600 .env
```

`.env` 已被 Git 忽略，不要提交真实密钥。

## 2. 启动完整演示

正式入口：

```bash
scripts/demo/start-local-demo.sh
```

macOS 可双击根目录的 `启动Reme全链路演示.command`。快捷方式最终调用 `reme.runtime.launcher`，不会在 `.venv/bin` 安装项目命令。

启动器会：

1. 检查统一后端 `8770` 和前端 `4174` 端口。
2. 读取仓库根目录 `.env`。
3. 检查前端原生依赖；缺失或跨平台不兼容时执行 `npm ci`。
4. 启动一个统一后端进程和一个 Vite 前端进程。
5. 等待两个服务就绪。
6. 在 `Ctrl+C` 时按进程组停止全部子进程。

验收地址：

```text
http://127.0.0.1:4174/typical-demo.html
```

调试信息默认展开：

```text
http://127.0.0.1:4174/typical-demo.html?debug=1
```

## 3. 运行结构

| 进程 | 地址 | 入口 | 用途 |
|---|---|---|---|
| 统一后端 | `127.0.0.1:8770` | `reme.runtime.server` | 摄像头输入、姿态、动作转变、规则/MiMo 决策、回应和危险确认 |
| 前端 | `127.0.0.1:4174` | Vite | 四场景单机演示页面 |

后端内部数据流：

```text
浏览器 /ws/camera-input
  → perception
  → 进程内 EventBroker / EventIngest
  → decision / MiMo
  → 浏览器 /ws
```

感知到决策不会经过本机 HTTP 或 WebSocket，也不会再启动第二个后端服务。HTTP/WS 只用于浏览器与统一后端之间的边界通信。

正式启动器默认使用浏览器 GPU 姿态推理：MediaPipe GPU delegate 在浏览器内生成 17 点关键点，再传给统一后端。GPU 初始化失败时页面会明确降级，不会静默改用 CPU。Debug 面板中的“推理后端”和“GPU 渲染器”可用于现场确认。

统一后端主要接口：

```text
GET  /api/health
GET  /api/runtime/capabilities
GET  /api/runtime/status
POST /api/runtime/start
POST /api/runtime/stop
WS   /ws/camera-input
WS   /ws/events?session_id=<id>
POST /api/session
POST /api/session/scene
POST /api/session/stop
POST /api/decision
POST /api/response
WS   /ws
```

`POST /api/events` 在统一运行时中被禁用；感知事件必须通过进程内传输进入决策模块。

## 4. 单独启动前端

只查看前端、不启动后端：

```bash
scripts/demo/start-frontend-preview.sh typical-demo.html
```

产品手机页：

```bash
scripts/demo/start-frontend-preview.sh index.html
```

兼容入口：

- `frontend/启动Reme典型场景演示.command`
- `frontend/启动Reme手机演示.command`

## 5. 单独启动统一后端

仅用于排障：

```bash
set -a
source .env 2>/dev/null || true
set +a
uv run --extra pose python -m reme.runtime.server \
  --host 127.0.0.1 \
  --port 8770 \
  --input-adapter c_ws_server \
  --browser-input-mode landmarks
```

前端环境变量全部指向同一后端：

```text
VITE_REME_PERCEPTION_HTTP_URL=http://127.0.0.1:8770
VITE_REME_PERCEPTION_INPUT_WS_URL=ws://127.0.0.1:8770/ws/camera-input
VITE_REME_DECISION_HTTP_URL=http://127.0.0.1:8770
```

## 6. 演示交互

`typical-demo.html` 包含客厅、厨房、浴室和跌倒场景。页面可查看：

- 感知会话、输入模式、帧龄、人物检测和姿态来源；
- 决策连接状态、规则/MiMo 输出和原始事件；
- 老人端和家属端的隐私视图；
- 安全回应、求助、厨房分享授权和手动跌倒调试入口。

“会话运行中”只表示运行时和 session 已启动，不代表已经检测到人物或动作。判断实时输入应查看帧龄、人物检测和关键点质量。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 端口已占用 | 关闭旧的统一后端或 Vite 进程后重试。 |
| 页面无法访问 | 查看 `[BACKEND]`、`[FRONTEND]` 日志，确认两个进程都已就绪。 |
| 页面显示等待运行时 | 打开 Debug，检查统一后端健康状态和摄像头权限。 |
| 摄像头没有画面 | 在浏览器和系统隐私设置中允许摄像头权限。 |
| 有画面但无骨架 | 让人物全身进入画面，并检查人物检测、关键点质量和输入模式。 |
| 没有 MiMo 决策 | 检查仓库根目录 `.env` 和 Debug 中的决策来源；确定性规则仍应正常工作。 |
| `Ctrl+C` 后页面仍可访问 | 正常退出应看到 `[FRONTEND] stopped` 和 `[BACKEND] stopped`；否则关闭遗留进程后重试。 |
