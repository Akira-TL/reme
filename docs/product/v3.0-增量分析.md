## 1. 六项重大增量（按影响排序）

### 1.1 原始视频策略回退：加密留存 → 纯内存（最大增量）

v2.0：骨架默认视图 + 原始视频本地 AES 加密留存 ≤7 天 + 高风险授权解锁片段 + 一键撤回。
v3.0：**"只在本机内存处理，不落盘、不上传"**；"机构证据模式"（加密短缓存、事件触发留存、访问审计）明确**不纳入 MVP**、需单独合规评估。

- 我们决议清单 D-04（三处留存口径矛盾裁决）**被 v3.0 直接裁决为"不落盘"**——且比我们的默认方案（±15s 片段）更彻底。G-06 三处文档同步的对象变为按 v3.0 口径统一。
- **SAFE-10/11/12/13 从"降级为模拟"变为彻底删除**（连模拟弹窗都不需要——没有解锁流程了）；UI-16 授权解锁入口删除。
- v2.0 答辩 Q5 的"刻意隐私分级"话术**作废**，新对外表达（v3.0 原文逐字）：“隐私不是给画面加一层滤镜，而是改变数据流：真实画面止于端侧，进入 Agent 的是事件，交付给家属的是行动。”（评委三点版本另有短句"隐私不是滤镜，而是数据边界"。）
- **连带撤销的两项承诺**：v2.0 §5.3 的"全部操作留痕可审计"与"一键撤回授权并清除数据"在 v3.0 消失（审计仅作为机构证据模式的未来研究项；撤回仅限"通知家属"的授权）。注意区分：SAFE-09 工程决策日志仍需保留（它是 v3.0 验收表的证据载体），删除的是面向用户的操作审计与数据清除产品承诺。

### 1.2 KPI 口径重构：撤销全部预承诺数字

v2.0 六项自测指标（≥95%、≤1%、≥5 轮、100%、≤500ms）→ v3.0 明确：**"不预先承诺 95%、1% 或 500ms"**，帧率/准确率/召回率/误触发率/P95 决策延迟全部**实测后填写**。新验收表六项：

| v3.0 验收项 | 标准 | 对应 v2.0 指标的变化 |
|---|---|---|
| 三类分流 | 每条路径连续 5 次成功 | 融合了"触发准确率 ≥95%"与"分流一致性 100%"，改为可复现性口径 |
| 决策结构 | MiMo 输出 JSON 解析成功率 100% | 新增（配合固定合同） |
| 隐私边界 | 原始视频不进任何网络请求 | PER-15 由"加分证据"升为**必过验收** |
| 安全兜底 | 高风险规则优先级不可被 MiMo 覆盖，**故障注入测试**为证据 | **SAFE-14 从我们的裁剪缓冲回升为必做**（反转） |
| 少打扰 | 普通确认 **1-3 轮**结束、可拒绝 | **方向反转**（注意口径对象不同：v2.0 的"≥5 轮"限定主演示，v3.0 的"1-3 轮"限定普通确认；主演示不再设轮次下限，其脚本约 3 轮恰好兼容） |
| 行动闭环 | 卡片含事件、原话、判断、动作、时效、**状态**六要素 | 五要素 → **六要素（新增"处理状态"）** |

- 决议 D-03（"≤500ms"口径矛盾）**被裁决**：不承诺，实测填写。
- **数字承诺连带撤销**：跌倒判定的"躯干角度突变＋重心骤降＋持续躺平 10 秒"三重量化条件与"30 秒倒计时"在 v3.0 只剩"疑似跌倒""语音确认与倒计时"——具体秒数/阈值归入 32-42h"阈值调整"实测确定，规则实现参数需在 0-4h 冻结时另行拍板，不能按 v2.0 数字硬编码。
- MIMO-06 验收需改写（普通确认 1-3 轮、主演示不设轮次下限）；DEL-12/13 KPI 方案按新验收表重做；"打扰率 ≤1%"删除，改用场景回放证明。

### 1.3 MiMo 合同字段化：D-01 契约被文档直接冻结

v3.0 给出固定输入/输出合同（v2.0 只有能力描述）：

- 事件输入：`event_type / duration / zone / pose_state / motion_level / confidence`
- 上下文输入：`time_context / baseline_summary / recent_events / dialogue_history`
- 决策输出：`risk_level / need_dialogue / dialogue_goal / opening / family_notification`
- 行动输出：`reason_summary / action_card / consent_required / fallback_action`

- 决议 D-01 的三份契约（事件 schema / MiMoResult / ActionCard）**答案已在文档里**——PER-05/SAFE-01/MIMO-04 的 schema 设计以此为准，第 0 步的"冻结"变为"按文档落地"。
- **新增字段注意**：`zone`（区域，如"餐桌旁"）是感知层新需求——PER-04/05 需要支持简单区域标定；`fallback_action`（降级动作）与 `consent_required`（授权前置）需进 SAFE-06 校验器与 MIMO-08。

### 1.4 范围收缩（砍掉约 1/3）

### 1.5 新增/升级要求

1. **家属端"处理状态"流转**（卡片第六要素 + "行动卡片与处理反馈"）——UI-11 需增加状态字段与流转展示（新→已确认→已处理）；
2. **老人端文字降级为 P0**（"语音失败时有文字降级；1-3 轮完成普通确认"）——我们"预置台词点选保底"的判断被确认且升级为 P0 硬要求；
3. **故障注入测试为验收证据**（安全兜底项）——SAFE-14 回升必做，从裁剪缓冲移出；
4. P1 新增：**家属误报/已处理反馈**（v2.0 没有的新功能）；**原画/骨架/事件三视图本地隐私演示切换**（PER-03 的 debug 对比开关被正名为演示功能）；
5. **3 分钟路演秒级分镜**：隐私冲突 20s → 定位 20s → 骨架与事件 50s → 牙疼闭环 70s → 跌倒兜底 30s → 生态价值 30s（DEL-19/21/23/24 的直接输入）；
6. 路演三记忆点与 30 秒版本定稿（"看见需要，不看见隐私"）。

## 3. 矛盾与需注意点

1. **骨架回放悬案**：v2.0 场景 C 承诺"家属端骨架回放了解事发经过"，v3.0 只字未提（家属端=事件/原话/行动）。建议明确砍掉 PER-17/UI-14 或降为 P2 彩蛋——不要按 v2.0 惯性继续做。
