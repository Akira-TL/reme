> **一句话定位 Reme
> 是可植入现有家庭摄像与语音设备的隐私关怀智能层：端侧把真实画面转成姿态与事件，由
> Xiaomi MiMo
> 判断是否介入、如何沟通，再把确认后的需求转成家属可执行的行动。**

## **本版冻结的五项决定**

- 产品形态：软件能力层，不自研新硬件。

- 唯一主场景：银发家庭，不扩展儿童、宠物、车内或机构取证。

- MVP 原视频策略：只在本机内存处理，不落盘、不上传。

- 主演示：长时间静坐 → 自然询问 → 发现牙疼 → 家属行动卡片。

- MiMo 合同：输入结构化事件，输出固定决策 JSON；高风险由规则状态机兜底。

# **01 产品定义**

## **目标用户与核心矛盾**

核心用户是高龄独居、空巢、白天独处或与子女异地居住的老人及其家庭照护者。家庭需要及时知道老人是否安全，但持续查看真实画面会侵犯尊严，并把持续判断的压力转嫁给家属。

## **Reme 解决的三重断点**

- 表达断点：老人不愿说、不会说，或突发情况下无法及时求助。

- 判断断点：设备发现变化，却不知道是否值得打扰、真实原因是什么。

- 行动断点：家属收到异常，却不知道先联系谁、准备什么、何时处理。

## **三项产品原则**

1.  隐私优先：少看、少传，原始画面默认不离开端侧。

2.  主动关怀：只在值得确认时开口，老人可拒绝、可随时结束。

3.  行动导向：输出具体下一步，而不是更多画面、数据或聊天记录。

## **产品边界**

| **Reme 是**                       | **Reme 不是**            |
|-----------------------------------|--------------------------|
| 可复用的隐私关怀软件能力          | 新的全天直播摄像头       |
| 连接感知、MiMo 与家庭行动的 Agent | 泛化 AI 陪聊机器人       |
| 发现、确认、分流和协同的闭环      | 医疗诊断或替代医生的系统 |
| 规则与大模型协作的安全系统        | 让大模型单独决定是否救援 |

# **02 核心体验闭环**

> **标准链路 本地感知 → 结构化事件 → 规则初筛 → MiMo 判断 → 自然确认 →
> 结果分流 → 家庭行动 → 反馈闭环**

## **主演示：从异常静坐到真实行动**

1.  本地姿态引擎发现老人在午餐时段长时间坐在餐桌旁。

2.  系统生成“静坐时间显著延长”的事件，不上传原始视频。

3.  MiMo 不直接判断生病，而是问：“今天午饭吃得还顺口吗？”

4.  老人回答：“牙疼，饭咬不动。”MiMo 只补齐必要信息。

5.  MiMo 询问是否愿意让家人知道，老人明确同意。

6.  家属收到行动卡片：今晚电话联系、准备软食、协助预约口腔门诊。

7.  家属点击“已确认”，老人端收到回执，闭环完成。

## **三类结果分流**

| **分支** | **系统行为**                   | **家属端**               | **证明点** |
|----------|--------------------------------|--------------------------|------------|
| 无需求   | 老人确认正常后立即结束，不追问 | 默认不推送，仅留低敏日志 | 少打扰     |
| 具体需求 | 确认原因与授权，生成行动建议   | 行动卡片 + 处理状态      | 理解并行动 |
| 高风险   | 规则接管，语音确认与倒计时     | 红色告警 + 联系人流程    | 安全兜底   |

# **03 比赛 MVP 范围**

MVP
成功标准：三类分支可以稳定、重复地从摄像头输入运行到家庭行动结果，并清楚证明
MiMo 的必要性与隐私边界。

## **P0：必须完成**

| **模块** | **最小能力** | **完成判定** |
|----|----|----|
| 端侧隐私感知 | 摄像头/本地视频接入；姿态关键点与时序特征仅本地处理 | 原始帧不进入网络请求 |
| 事件与规则引擎 | 正常、长时间静止、疑似跌倒；去抖、阈值、状态恢复 | 三类事件可重复触发 |
| MiMo 关怀 Agent | 介入判断、对话规划、需求理解、结果分流、行动建议 | 固定 JSON 可稳定解析 |
| 老人端 | 短对话、可拒绝、授权提示；语音失败时有文字降级 | 1-3 轮完成普通确认 |
| 家庭端 | 事件、老人原话、判断、建议、时效、处理状态 | 卡片要素完整 |
| 演示工具 | 实时 / 剧本 / 录制三模式；时间加速明确标注 | 断网或光线异常仍可演示 |

## **P1：完成 P0 后再做**

- 个人生活基线与家属误报/已处理反馈。

- 基于事件摘要的每日关怀日记；默认关闭，需老人授权。

- 原画、骨架、事件视图的本地隐私演示切换。

## **明确不做**

自研摄像硬件、多房间多人追踪、毫米波融合、机构取证、医疗诊断，以及儿童/宠物/车辆等平台化场景。

# **04 技术架构与 MiMo 职责**

## **四层职责**

| **层级** | **输入** | **输出与责任** |
|----|----|----|
| 端侧感知 | 本地视频帧 | 关键点、姿态、位置、速度、时长；不输出身份与画面 |
| 规则安全层 | 连续事件流 | 去抖、阈值、风险等级、倒计时与强制告警 |
| MiMo 认知中枢 | 事件 + 时段 + 基线 + 对话摘要 | 是否介入、怎么开口、需求理解、结果分流、行动建议 |
| 家庭行动端 | 决策 JSON + 老人授权结果 | 事件时间线、关键原话、行动卡片与处理反馈 |

## **MiMo 固定输入/输出合同**

| **方向** | **核心字段** |
|----|----|
| 事件输入 | event_type / duration / zone / pose_state / motion_level / confidence |
| 上下文输入 | time_context / baseline_summary / recent_events / dialogue_history |
| 决策输出 | risk_level / need_dialogue / dialogue_goal / opening / family_notification |
| 行动输出 | reason_summary / action_card / consent_required / fallback_action |

> **安全优先级 高风险规则状态机 \> MiMo 输出。MiMo
> 可以生成解释和沟通文案，但不能取消确定性告警，也不能输出医疗诊断。**

## **实现策略**

- 姿态模型选型以能稳定输出时序关键点为准，不把关键点数量当创新。

- MiMoClient 同时支持 live / mock /
  record，现场网络异常时不影响产品闭环。

- 所有模型输出先做 schema 校验；超时、解析失败或越界内容自动降级。

# **05 隐私与安全边界**

> **比赛版最终口径
> 原始视频只在本机内存中用于实时姿态提取；不落盘、不上传，也不向家属提供持续实时观看。**

## **五条硬规则**

- MiMo 只接收结构化事件与必要对话文本，不接收原始视频。

- 系统保存关键点摘要、事件、授权结果与家属处理状态，不保存全天行为录像。

- 普通需求在通知家属前优先征得老人授权；老人可以拒绝或撤回。

- 演示中的原画/骨架对比只在本地验证转换有效，不代表家属默认可看原画。

- 高风险流程由确定性规则兜底，大模型不能压制或延迟必要告警。

## **两种模式必须分开**

| **模式** | **原始影像策略** | **当前状态** |
|----|----|----|
| 家庭关怀模式 | 默认不留存；家属只看事件、对话摘要和行动结果 | 本次比赛唯一模式 |
| 机构证据模式 | 未来可研究端侧加密短缓存、事件触发留存与访问审计 | 不纳入 MVP，需单独合规评估 |

## **对外表达**

隐私不是给画面加一层滤镜，而是改变数据流：真实画面止于端侧，进入 Agent
的是事件，交付给家属的是行动。

# **06 演示与验收**

## **三层演示保底**

1.  主模式：笔记本摄像头实时输入，现场完成姿态、事件、MiMo
    与家庭端闭环。

2.  剧本模式：一键触发无需求、具体需求、高风险三条路径，避免光线与动作识别翻车。

3.  录制模式：保留完整屏幕录制与 GIF，仅作为极端情况下的备份。

## **三分钟顺序**

隐私冲突 20 秒 → 一句话定位 20 秒 → 端侧骨架与事件 50 秒 → 牙疼行动闭环
70 秒 → 跌倒规则兜底 30 秒 → 小米生态价值与边界 30 秒。

## **必须通过的验收项**

| **验收项** | **通过标准**                             | **证据**          |
|------------|------------------------------------------|-------------------|
| 三类分流   | 每条路径连续 5 次运行成功                | 演示日志          |
| 决策结构   | MiMo 输出 JSON 解析成功率 100%           | 结构化日志        |
| 隐私边界   | 原始视频不进入任何网络请求               | 网络记录/代码检查 |
| 安全兜底   | 高风险规则优先级不可被 MiMo 覆盖         | 故障注入测试      |
| 少打扰     | 普通确认在 1-3 轮结束，可拒绝            | 场景回放          |
| 行动闭环   | 卡片含事件、原话、判断、动作、时效和状态 | 家属端截图        |

指标口径：帧率、事件准确率/召回率、误触发率和 P95
决策延迟均在实测后填写；不预先承诺 95%、1% 或 500ms。

# **08 路演核心叙事**

> **30 秒版本
> 很多家庭为了安全给独居老人装摄像头，但摄像头越清晰，老人的生活就越像被直播。Reme
> 不把更多画面推给家属，而是在设备本地把画面转成姿态和事件，只在发现值得确认的变化时，由
> Xiaomi MiMo
> 自然地问一句，再把老人确认后的需要变成家属马上可以执行的行动。**

## **评委必须记住的三个点**

1.  隐私不是滤镜，而是数据边界：原始画面默认止于端侧。

2.  MiMo
    不是聊天插件，而是认知中枢：决定何时问、怎么问、如何理解和如何分流。

3.  输出不是报警，而是行动：让家属知道下一步具体做什么。

**看见需要，不看见隐私。**
