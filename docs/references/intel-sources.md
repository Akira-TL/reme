# 情报来源台账（MiMo API · Miloco · 竞品对照）

与 [cognition-evidence.md](cognition-evidence.md) 同一套规矩，只是对象从学术文献换成了**会变的外部事实**：官方文档、开源仓库、我们自己的实测。凡进入答辩话术、成本估算或架构决策的外部事实，必须能在这里查到出处、核实日期与可信级别。

## 使用规则

1. **区分三个可信级别**，不得混用：
   - `[实测]` — 我们自己跑出来的结果，最高可信，但只对我们跑过的条件成立。
   - `[官方声称]` — 官方文档写的，未经我们验证。
   - `[二手]` — 第三方转述/未读原帖，**不得作为答辩依据**，只作线索。
2. **外部事实会过期**：每条记核实日期。定价、限流、许可证、模型名单尤其易变，**答辩前必须重新核对本表标 ⏳ 的条目**。
3. **许可证红线优先于一切便利**：见文末合规表，违反项直接否决方案，不进入取舍讨论。
4. 与源文档冲突时以本表为准（本表记的是最近一次实际核实的结果）。

## 一、Xiaomi MiMo 开放平台（我们的认知中枢供应商）

### S1 · API 端点与模型名 ⏳

- 来源：<https://mimo.mi.com/static/docs/api/chat/openai-api.md> `[官方声称]` · 核实 2026-08-02
- 核实结果：base URL `https://api.xiaomimimo.com/v1/chat/completions`；模型 `mimo-v2.5`、`mimo-v2.5-pro`。平台自述兼容 OpenAI 与 Anthropic 两种 API 格式（另有 Anthropic 兼容端点 `https://api.xiaomimimo.com/anthropic`）。
- 交叉验证：`[实测]` 2026-08-01 —— **官方模型名可直接使用，无需 `xiaomi/` 前缀**（该前缀是 OpenRouter 的写法，两者不可混）。

### S2 · 计费 ⏳

- 来源：<https://mimo.mi.com/static/docs/price/pay-as-you-go.md> `[官方声称]` · 核实 2026-08-02
- 核实结果（每百万 token，国内价）：

  | 模型 | 输入（缓存未命中） | 输入（缓存命中） | 输出 |
  |---|---|---|---|
  | mimo-v2.5 | ¥1.00 | ¥0.02 | ¥2.00 |
  | mimo-v2.5-pro | ¥3.00 | ¥0.025 | ¥6.00 |

  另有海外美元价（v2.5：$0.14 / $0.0028 / $0.28）；缓存写入限时免费；TTS 当前免费。
- **本次核实新增的事实**：早前情报只记了 ¥1/¥2，没有**缓存命中价低两个数量级**这一条。我们的三任务提示词共享大段固定系统提示，命中缓存时成本远低于按 ¥1 估算的结果——成本叙事可据此更新。

### S3 · 限流 ⏳

- 来源：<https://mimo.mi.com/static/docs/api/guidance/rate-limit.md> `[官方声称]` · 核实 2026-08-02
- 核实结果：`mimo-v2.5` 与 `-pro` 均 **100 RPM / 10M TPM**；ASR 为 100 RPM / **10K** TPM（与文本模型差三个数量级，做语音时按此规划）；限流按账户跨全部 key 合并计算；官方明确提示服务端负载高时可能 429，建议实现重试与退避。
- 对我们的影响：`MimoClient` 的重试仅针对 429/5xx 且带单调截止预算——与官方建议一致。实验台的 `--pace` 默认 0.7s（约 85 RPM）也是据此设的。

### S4 · 我们的 live 实测（G-01） `[实测]`

- 来源：`.scratch/handoff/2026-08-01-mimo-api-live-test.md`（**在 `mimo-api-research` 分支，不在 `b-decision`**）· 2026-08-01
- 结果：最小调用 200；直连冷连接 0.51–2.03 s；决策 JSON mode 5/5 九字段全齐；真实 POST 响应含 `access-control-allow-origin: *`（浏览器直连可行）；`image_url` base64 PNG 200；**`video_url` base64 mp4 200 且回答有画面依据**（V 路径视频通道成立，无需降级为关键帧）。
- 两条写提示词时必须知道的观察：分支波动明显 → 决策调用显式 `temperature≈0.2`；称呼漂移（老先生/奶奶/爷爷混用）→ 称呼必须从配置注入、不让模型猜性别。
- 后续放大验证：S10 的大样本实验把"5/5"扩到 **240 次真调用零失败**（见 `.scratch/mimo-decision-interaction/results/2026-08-01-prompt-experiment.md`）。
- **不成立的推广**：这些延迟数字来自我们的网络与时段，不是服务等级承诺；`video_url` 用的是 64×64 合成测试片，**真实居家画面的识别质量未测**。

## 二、Xiaomi Miloco（同生态对照项目 · 合规高风险）

### S5 · 项目性质与许可证 🚨

- 来源：<https://github.com/XiaoMi/xiaomi-miloco>（另有 <https://gitee.com/xiaomi-miloco>）`[官方声称]` · 核实 2026-08-02
- 项目性质：小米开源的全屋智能方案，用摄像头感知 + 大模型实现主动式设备控制。
- **许可证限制（核实原文要点）**：项目声明**仅供非商业用途**；未经小米公司书面授权，不得用于开发应用程序、网络服务或其他形式的软件。
- **由此产生的硬红线（不可协商）**：
  1. **零代码复用** —— 一行都不抄，不 fork，不改写。
  2. **不得宣称** Reme 基于 Miloco 开发、衍生或二次开发。
  3. 不使用小米/米家品牌标识作为我方产品元素。
  4. 对照分析只能用于**说明差异**，不能作为实现参考落到代码里。

### S6 · Miloco 架构对照（差异叙事的事实基础）

- 来源：`planning/docs/情报-Miloco-代码剖析.md`（**在 `mimo-api-research` 分支**）`[二手/读码]` · 2026-08-01
- 用于对照的关键差异：Miloco 在每个触发窗口把**原始 mp4 片段 + 人脸库 + 家庭档案**发往云端；Reme 的对照面是"画面转骨架、原始帧不出户、按需最少视觉上下文"（ADR-0001/0003）。
- **叙事纪律**：这是**能力取向差异**，不是优劣评判——"Miloco 追求看得更懂，Reme 坚持看得更少"。任何把对方说成"隐私有问题"的表述都超出了事实，也无必要。
- ⚠️ 该文档基于某一时点的代码阅读，上游随时可能变；**引用前须重新读码**，不得把旧结论当现状。
