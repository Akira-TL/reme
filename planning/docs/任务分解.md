## 3. 关键路径（通往"场景 B 主演示跑通"）

终点判据（DEL-09）：摄像头→火柴人→静坐触发→对话→行动卡片→家属确认→老人端回执，**连续多次全通过（v3.0 验收口径：每条路径连续 5 次）**。

1. MIMO-01 — 仓库初始化+MiMo API 最小调用跑通，是全部工程、契约与模式选择的前置
2. SAFE-01 — 四方数据契约与风险三级口径冻结（事件/MiMoResult/ActionCard），8h 内必须完成否则全线返工
3. PER-05 — 去身份化事件 schema 与事件总线落地（与 SAFE-01 同步冻结，MiMo/SAFE/家属端共同消费）
4. PER-01 — 浏览器摄像头采集与帧管道（原始画面仅内存）
5. PER-02 — MediaPipe 33 关键点本地推理（wasm 本地打包、断网可用）
6. PER-04 — 姿态特征提取与体位分类（静坐规则的输入）
7. PER-12 — 虚拟时钟 DemoClock（45 分钟压缩为数秒的计时基座）
8. PER-06 阈值配置冻结（v3.0：固定阈值替代基线 P95，与剧本文案对齐）
9. PER-06 — 静坐时间显著延长规则触发（场景 B 的事件源，固定阈值）
10. MIMO-02 — MiMoClient 三模式统一入口（live/mock/record，断网保底）
11. MIMO-03 — 人设 prompt 与含蓄口语化理解（『饭咬不动』→饮食+口腔标签）
12. MIMO-04 — 结构化输出协议+校验重试+超时降级
13. MIMO-05 — 介入判断：事件+时段+基线 → 关切开场
14. MIMO-06 — 对话管理状态机（普通确认 1-3 轮）、『不想聊了』即停
15. MIMO-07 — 三分支分流（场景 B 走 need 分支）
16. MIMO-08 — 行动卡片生成（老人授权前置+六要素完整）
17. UI-02 — 双端事件总线（卡片下发与回执回传的唯一通道）
18. UI-11 — 家属端行动卡片渲染+『已确认』按钮
19. MIMO-09 — 确认事件→老人端回执编排
20. UI-07 — 老人端回执展示+TTS 播报（闭环最后一秒）
21. DEL-09 — 实时主模式 E2E 串测：摄像头→火柴人→静坐触发→对话→卡片→确认→回执连续 3 次通过＝场景 B 跑通的中间里程碑（S3 收口按 v3.0 每路径连续 5 次）

#### PER-01 · 浏览器摄像头采集与视频帧管道

`P0 · 1.5h · 梁博星`

**目标**：getUserMedia 拿到本地视频流并建立帧处理管道，原始画面仅存在于内存，不落盘、不显示给评委

**步骤**：
- getUserMedia 请求 720p 视频流，绑定到隐藏 video 元素（老人端页面不渲染原始画面）
- requestVideoFrameCallback/requestAnimationFrame 建立逐帧回调管道，暴露 onFrame 钩子供推理层消费
- 处理权限拒绝、无摄像头、设备被占用三种失败态，页面给出明确降级提示文案
- 支持多摄像头枚举与切换（现场可能用外接 USB 摄像头调角度）

**验收**：
- [ ] Chrome 打开页面授权后视频流跑通，720p 下帧管道稳定 ≥15fps（控制台打印实测 fps）
- [ ] 页面 DOM 中不可见任何原始画面元素（video 隐藏，无 img/canvas 绘制原图）
- [ ] 拔掉摄像头/拒绝授权时出现降级提示而非白屏报错
- [ ] 可在设置里切换内置/外接摄像头并即时生效

依赖：`MIMO-01` ｜ 风险：现场笔记本摄像头位置低、俯仰角不佳影响后续跌倒判定，需配合外接摄像头预案

#### PER-02 · MediaPipe Pose 本地推理集成（离线可用）

`P0 · 2h · 梁博星`

**目标**：接入 MediaPipe Pose（33 关键点）在浏览器 wasm 本地实时推理，模型与 wasm 资产全部本地打包，现场断网也能跑

**步骤**：
- 引入 @mediapipe/tasks-vision PoseLandmarker，选 lite 模型权衡帧率
- 将 wasm 与 .task 模型文件下载进仓库本地静态目录，禁止运行时走 CDN（现场网络保底）
- 接 PER-01 的帧管道做逐帧推理，输出 33 关键点归一化坐标 + 可见度
- 推理放 VIDEO 模式复用时序信息，记录每帧推理耗时

**验收**：
- [ ] 演示笔记本上实测端到端（采集+推理）≥15fps，单帧推理耗时日志可查
- [ ] 断网（关 Wi-Fi）刷新页面后推理仍正常工作——DevTools Network 无任何 CDN 请求
- [ ] 站/坐/躺三种姿态下 33 关键点稳定输出，主要关键点可见度 >0.5

依赖：`PER-01` ｜ 风险：现场演示机性能未知，lite 模型帧率不达标需降分辨率兜底；逆光/暗光下关键点抖动大

#### PER-03 · 火柴人骨架实时渲染

`P0 · 1.5h · 梁博星`

**目标**：Canvas 上只画火柴人骨架（连线+关节点），评委亲眼验证'画面不出设备'，这是产品核心卖点的视觉呈现

**步骤**：
- 按 MediaPipe 骨架拓扑连线绘制火柴人，风格适配老人端 UI（线条粗、对比度高）
- 对关键点做一帧级 EMA 平滑消抖，低可见度关键点断线处理而非乱飞
- 画布上叠加常驻隐私标注文案：'原始画面仅本地内存处理，仅显示骨架'
- 预留 debug 开关（默认关）：开发期可叠加半透明原图对位调试，演示构建禁用该开关

**验收**：
- [ ] 真人在镜头前走动，火柴人跟随渲染延迟目测 <100ms、无明显抖动

#### MIMO-01 · MiMo API 最小调用跑通（live 模式地基）

`P0 · 1h · 谭朗`

**步骤**：

- 确认是否支持流式输出、system prompt、JSON 输出约束等能力，记录到 README

**验收**：
- [ ] 脚本运行即返回 MiMo 中文回复，无鉴权/跨域错误

#### MIMO-03 · 系统提示词与人设：含蓄口语化理解、不做医疗诊断

## 8. 验收标准修正（批判校验遗留，仍适用的部分）

以下为 v2.0 阶段批判校验发现的验收弱点，涉及被删任务的条目已失效，其余仍适用：

- PER-03：『火柴人跟随渲染延迟目测 <100ms、无明显抖动』——100ms 级延迟无法目测，『无明显抖动』纯主观；应改为时间戳打点或 240fps 录屏逐帧测量，并给抖动定义量化判据（如相邻帧关键点位移方差阈值）。
- UI-03：『目测无明显拖影，帧率 ≥15fps』——帧率可测但『无明显拖影』不可验证，且与 PER-03 是同一功能的重复验收（两个任务、两套口径），需统一并量化。
- DEL-05：『非团队成员朗读反馈已记录并处理』『3 段 MiMo live 输出抽查与剧本风格一致性确认』——『已处理』『一致性确认』均无通过/不通过判据，建议改为清单式评分（如朗读者对每段台词打分 ≥4/5、风格差异项清零或有豁免记录）。
- DEL-11：『主参数下坐姿与躺姿关键点均持续可检出（目测无长时间丢失）』——『长时间』未定义，应量化为如『连续丢失 <1 秒、10 分钟内累计丢失时长占比 <5%』。
- MIMO-13：『风格接近 PRD 示例（江婷芳验收）』——纯主观验收，建议附风格 checklist 逐项勾检：≤120 字、含 1 条明日建议、无诊断词、每句可回溯到输入事件、含情绪/状态描述。
- PER-15：『代码走查记录：无图像外发路径』——人工走查不可复现，建议补自动化断言：grep canvas.toDataURL/toBlob/ImageCapture/getUserMedia 流外发 + DevTools 网络请求白名单脚本化检查，输出可归档报告。
- UI-05：『真人说话时 500ms 内出现聆听动画』——未说明测量方法，500ms 无法肉眼判定，需用事件时间戳日志或录屏帧计数验证。
- MIMO-14：『连测 3 次成功 ≥2 次』——作为 P0 主演示路径，33% 的容忍失败率过弱且未定义失败时的现场判据；应与 DEL-17 降级决策树对齐（如『连续 2 次识别失败即切点选兜底』）并把彩排通过标准提高。
- DEL-03：『结论表覆盖全部拟投赛事』——『全部拟投赛事』清单由本任务自我定义，缺外部核对项；建议加『清单经队长确认无遗漏』的签字项。

## 9. 风险清单（v2.0 阶段识别，标注 v3.0 后状态）

1. 谭朗单点风险：关键路径 21 项中 13 项、MIMO+SAFE 两个子系统全在他名下且负载约 2 倍于可用工时；他卡壳或倒下即全盘停摆。0-8h 必须完成上述改派与裁剪清单，并让 MIMO-06/08 先用 mock 与 UI 假集成并行。【v3.0 后缓解：SAFE-10~13 删除、日记/基线降级，负载降至可行区间，主链保护原则不变】
