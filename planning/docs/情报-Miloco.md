## 1. 事实清单

| 项 | 内容 |
|---|---|
| xiaomi-miloco/xiaomi-miloco | 官方开源全屋智能 AI 平台（Miloco 2.0，2026-06-18 发布）。米家摄像机为视觉信息来源、自研 MiMo 大模型为核心；感知引擎→规则系统→MIoT 网关控制设备。Python(FastAPI)+React，以 OpenClaw 插件形态运行，提供 Agent Skill 扩展机制 |
| 五大能力 | 通用常识告警（无需预设规则）、身份识别（人脸+体态）、家庭记忆（长期习惯）、家务任务、主动智能 |
| MiMo 调用方式 | **云 API（多模态，持续产生调用费用）**——原始视频/图像出端进云 |
| xiaomi-miloco/xiaomi-mimo-vl-miloco | **MiMo-VL-Miloco-7B**：家庭场景理解专训的 7B 视觉语言模型，图像+视频输入，权重开放（HuggingFace/ModelScope，含 GGUF 量化），可 Gradio 本地推理，`/no_think` 可关思维链 |
| 许可证 | **两仓库均限非商用**；未经小米书面授权不得用于开发 APP/网络服务 |
| 部署门槛 | ≥4GB RAM、≥256GB 存储、24/7 运行（推荐 Mac mini）、小米账号+已有设备、多模态大模型 API |

## 2. 对 Reme 的六点影响

1. **雷区（最高优先级）**：v2.0 曾写"小米人车家生态在此场景尚无原生能力，这正是 Reme 的生态位机会"——**Miloco 2.0 两个月前就发布了，评委必然知道**。任何"填补空白"话术当场穿帮。v3.0 已删竞品章节，但团队口头表达和 PPT 素材中此话术必须清零（并入 DEL-10 口径终检检索项）。
2. **新必答题**："Reme 和 Miloco 什么关系/区别？"必进新问答集（DEL-10 问答素材重写时置顶）。参考答案框架：Miloco 证明了"摄像头+MiMo 主动智能"是小米官方方向；它面向全屋智能，把原始画面交给云端多模态模型换取"看得更懂"；Reme 面向银发这个隐私最敏感的场景，把画面在端侧压成火柴人事件，只让去身份化结构化数据进大模型——**同一生态，Miloco 追求看得更懂，Reme 坚持看得更少**，两者是互补层不是竞争者。
3. **"生态价值 30 秒"素材有了答案**（G-08 改写项落点）：Reme 的生态位＝Miloco 生态的**隐私关怀垂直层**——银发场景专精（少打扰原则、家属行动卡片闭环）＋隐私数据边界（事件而非画面）。比"零成本激活存量摄像头"的旧叙事更扎实，因为它站在官方平台的延长线上。
4. **技术接入参考**（MIMO-01/G-04 输入）：Miloco 的 MiMo API 接入方式是竞赛 API 形态的最佳线索；**MiMo-VL-Miloco-7B 的 GGUF 量化本地推理是 live API 拿不到时的第四层预案**（live/mock/record 之外），但 48h 内跑 7B VL 风险高，仅作调研备注不进排期。
5. **许可证红线**：两仓库均"非商用＋未经授权不得开发 APP"。**Reme 不要宣称"基于 Miloco 二次开发"**——保持独立实现＋生态互补叙事，既是许可证安全也是原创性声明（附录 B 报备口径）安全。商业价值页的表述也要避免暗示直接复用 Miloco 代码。
6. **差异化论据被动强化**：Miloco 的云 API 计费与视频出端，反向印证了 Reme 三条硬主张的价值——纯内存处理（隐私）、去身份化事件（数据最小化＝API 成本最小化）、浏览器端零部署门槛（对比 Mac mini 24/7）。答辩 Q"为什么不用多模态大模型直接看画面"现在有了官方参照系。
