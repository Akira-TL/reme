**二、作品主题与定位**

**2.1 一句话定位**

**Reme 是一套以 Xiaomi MiMo
为认知中枢的隐私优先型主动关怀软件系统：不售卖任何新硬件，以"软件转接头"形态接入家庭已有摄像头（优先适配米家生态），将监控画面转化为火柴人骨架视图，把老人未主动表达的困难，转化为家属可执行的关怀行动。**

**2.2 三大原则**

**01 隐私优先**

面向家属的默认视图是火柴人骨架——只保留动作、位置、时长，不保留外貌与环境细节。原始画面仅在本地内存中实时处理，不落盘、不上云。原始视频以加密形式本地留存不超过
7
天滚动删除；仅在确认高风险事件且老人授权（或紧急情况下的紧急联系人协议）后，方可解锁对应片段。授权全程可撤回。

**02 主动关怀**

基于 MiMo
判断介入时机，摒弃机械定时问候。通过自然语音交互主动感知老人状态与情绪，像家人一样发起有温度的对话。

**03 行动导向**

拒绝做无意义陪聊的
AI。确认需求后生成家属可执行的行动卡片，并通过每日"时间线日记"保持低打扰的情感连接，推动真实家人的及时照护。

**2.3 产品边界**

AI
负责感知、理解与协调；不提供持续监控画面；不做医疗诊断；不替代家人陪伴。

**三、需求洞察**

**3.1 真实痛点（团队亲历）**

> *“"我奶奶 70
> 多岁，独居农村。子女为了安全给她装了摄像头。夏天她洗完澡为了省电，光着身子在屋里扇风——被高清镜头看得一清二楚。摄像头保住了安全，却拿走了尊严。"”*

中国农村约 34%
的老人独居，子女安装摄像头已成常态，而老人的"被监视感"与隐私羞耻是一种沉默的普遍情绪。现有摄像头厂商竞逐更高清晰度，完全忽略了被看护者的尊严需求——这是市场空白，也是本项目的切入点。

**3.2 市场证据**

- 东软睿新 2026 年 5
  月发布"火柴人"养老记录仪：隐私化设计使养老机构家属同意率从 **32%
  提升至 98%**——隐私设计是此类产品能否进门的生死线。

- 亲鹿看护机（原小天才团队创业）主打家庭跌倒检测，C
  端月营收超百万——家庭付费意愿已被验证。

- 华为 2024 年推出 AI
  辅助康养传感器——大厂已入场；而**小米"人车家"生态在此场景尚无原生能力**，这正是
  Reme 的生态位机会。

**3.3 现有方案的三重缺陷**

1.  **传统摄像头**：提供实时画面，却把持续查看与判断的负担留给家属，老人有被监视感；

2.  **单点报警器**：只识别单一触发条件，不理解异常背后的真实原因，误报频发；

3.  **被动语音助手**：等待主动唤醒，而老人常因怕麻烦、不熟悉操作或不愿示弱而沉默；

4.  **新一代火柴人硬件**（东软、亲鹿等）：全部需要购买新设备，且止步于"检测→告警"，没有解决"家属知道异常后该做什么"。

**3.4 核心洞察**

突发意外往往是长期隐患的爆发。食欲骤降、持续久坐、行动变慢等"非紧急异常"，才是最需要被捕捉的早期信号。真正缺失的不是更多监控，而是一条
**"发现变化—适度询问—确认需求—推动行动"** 的闭环。

**四、核心场景与交互闭环**

比赛版本聚焦一个可复现、可验证、可演示的居家场景，三条分支完整覆盖分流逻辑。

**4.1 场景 B（主演示）：具体需求 → 行动卡片**

下午，系统识别到老人在餐桌旁连续静坐 45 分钟（超出个人基线 P95）。MiMo
不直接质问身体异常，而是自然切入：

- **MiMo**："今天午饭吃得还顺口吗？"

- **老人**："牙疼，饭咬不动。"

- **MiMo**："牙疼啊，那吃着费劲。是这两天一直疼，还是就今天？"

- **老人**："疼了两天了，今天基本没吃。"

- **MiMo**："这样，我跟孩子说一声，让他帮您看看怎么办，行吗？"

- **老人**："行，你说吧。"

获得授权后，家属端收到行动卡片：

5.  今晚电话联系老人，确认疼痛程度；

6.  明早准备软烂食物（粥、蒸蛋）；

7.  24 小时内协助预约口腔门诊。

家属点击"已确认"后，老人端收到回执："孩子已经知道了，晚点给您打电话。"——**闭环的最后一秒，是全场最打动人的设计。**

**4.2 场景 A：无需求 → 温和结束（少打扰的证据）**

老人下午看电视静坐 40 分钟（轻度偏离基线）。MiMo
寒暄两句，老人表示"一切正常"，系统立即结束交流，仅在时间轴记录一条灰色日志，**不推送家属**——对应"打扰率
≤1%"的承诺。

**4.3 场景 C：高风险 → 规则状态机接管**

识别到疑似跌倒（躯干角度突变 + 重心骤降 + 持续躺平 10
秒）后，**系统不经过大模型决策**，由规则安全状态机直接接管：语音确认"您还好吗？"并启动
30
秒倒计时；无响应则家属端触发红色告警并模拟通知紧急联系人。家属端默认提供**骨架回放**了解事发经过；查看原始影像片段需走授权解锁流程。

**4.4 新增亮点：MiMo 时间线日记**

每日 21:00，MiMo 将当日事件流生成一段温暖的生活日记推送家属：

> *“"妈今天看了 3
> 小时戏曲，精神不错。午饭吃得比平时少，傍晚在餐桌旁坐了很久——明天提醒她吃点软的，顺便问问牙。"”*

这是规则引擎无法实现、家属每天真的会打开看的功能，是"少打扰"原则下保持情感连接的设计，也是
MiMo 语义理解能力最直观的展示。

**五、基于 Xiaomi MiMo 的技术方案**

**5.1 四层架构**

> 端侧隐私感知 → MiMo 认知中枢 → 规则安全层 → 家庭行动端

**01 端侧隐私感知**

基于成熟开源姿态估计模型（33
关键点级别）在本地实时推理，视频帧仅在内存中处理。自研异常行为规则引擎：连续静坐超时、疑似跌倒（躯干角突变 +
重心骤降 +
持续低位三重条件）、非常规时段躺卧、活动量较基线骤降、夜间徘徊。规则阈值参考公开学术论文并经实测标定。仅输出"连续静坐
45 分钟"等去身份化事件。

**02 MiMo 认知中枢（系统的大脑）**

四大核心能力 + 一项生成能力：

- **介入判断**：结合事件、时段与个人生活基线，避免"一异常就报警"；

- **对话管理**：选择自然开场方式，实时决定继续、换话题或结束；

- **需求理解**：解析老人含蓄、口语化的表达（"饭咬不动"→
  饮食与口腔问题），结合上下文补全语义，但不作医疗诊断；

- **行动编排**：将结果分流为"无需求 / 具体需求 /
  高风险"，生成家属可执行的行动建议；

- **日记生成**：将每日事件流转化为有温度的时间线日记。

**MiMo 的不可替代性**：若移除
MiMo，系统将退化为只能按固定阈值报警的传统监测设备——无法理解原因、无法确认需求、无法编排行动。这是本项目在
MiMo 竞赛单元的核心价值主张。

**03 规则安全层**

高风险事件进入确定性状态机，优先级高于大模型输出。MiMo
的全部输出经过结构化校验与风险检查，超时自动降级到规则决策。

**04 家庭行动端**

时间轴呈现事件全貌，行动卡片包含五要素：发生了什么、老人怎么说、系统判断、建议动作、时效。**不提供实时画面**，骨架回放为默认，原始影像需授权解锁。

**5.2 纯软件部署形态（"转接头"的商业本质）**

- **形态一（目标态）**：米家摄像头 / 家庭中枢的 OTA 功能"AI
  关怀隐私模式"，类红米手机自带 AI 反诈的卖点逻辑；

- **形态二（过渡态）**：旧手机 / 平板安装 App 改造为关怀终端；

- **形态三（通用态）**：品牌无关的局域网视频流处理软件，适配第三方摄像头。

比赛版本在浏览器中完整验证"摄像头 → 骨架 → 事件 → MiMo 决策 →
家属端"全链路，证明软件方案不依赖专用硬件。

**5.3 数据与隐私设计**

数据最小化；骨架事件不出设备（比赛版仅事件与对话文本经由 API 与 MiMo
交互）；原始视频本地 AES 加密、7
天滚动删除、授权解锁、全部操作留痕可审计；用户可随时一键撤回授权并清除数据。

**六、创新性与竞争优势**

**6.1 真实竞品对比**

| **维度** | **东软睿新"火柴人"** | **亲鹿看护机** | **华为 AI 康养传感器** | **Nobi 智能灯** | **Reme** |
|----|----|----|----|----|----|
| 产品形态 | B 端监管记录仪 | C 端看护硬件 | 毫米波传感器 | B 端智能灯具 | **纯软件转接头，零新增硬件** |
| 隐私方式 | 本地转火柴人，不存原始影像 | 日常线稿，**异常时切换高清录像** | 无摄像头 | 本地处理，告警图可选抽象化 | 骨架为默认视图，原始影像本地加密 + 分级授权 |
| 交互能力 | 无 | 无主动对话 | 无 | 跌倒后语音确认 | **MiMo 主动多轮自然对话** |
| 输出结果 | 机构监管报告 | 告警电话 | 分级告警 | 告警 + 跌倒分析 | **家属行动卡片 + 每日时间线日记** |
| 目标市场 | 养老机构 / 长护险监管 | C 端家庭（硬件销售） | 全屋智能用户 | 养老机构 | C 端存量摄像头家庭，低中端 |

**6.2 三大差异化**

8.  **纯软件 vs 全卖硬件**：所有竞品都要求购买新设备；Reme
    让家庭已有摄像头（尤其米家存量设备）通过软件升级获得能力，适配成本趋近于零，覆盖更广泛的低中端家庭。

9.  **认知中枢 vs
    检测告警**：竞品的终点是"把异常通知家属"，判断与行动的负担仍留给家属；Reme
    用 MiMo 完成"询问—确认—编排"，交付的是可执行方案。

10. **彻底隐私 vs 隐私留白**：亲鹿在异常时切换真实录像；Reme
    全程骨架为默认，原始影像的分级授权机制把选择权交还老人。

**6.3 打通三重断点**

- 老人不主动说 → 主动发现值得确认的变化；

- 机器不知道何时问 → 基于个人基线选择时机；

- 家属知道后不会做 → 输出具体、可执行的建议。

**八、未来展望与商业潜力**

**8.1 演进路径**

- **短期**：米家摄像头 / 家庭中枢 OTA"AI 关怀隐私模式"，激活存量设备；

- **长期**：连接社区养老、家庭医生与照护机构的分级服务，坚持知情同意、数据最小化、人工最终决策。

**8.2 商业价值**

- **存量硬件价值重构**：为小米已有摄像头产品线提供零成本差异化卖点（类比红米
  AI 反诈的传播逻辑），提升竞争力与用户粘性；

- **C 端订阅**：家庭关怀月费（日记、行动卡片、分级告警）；

- **B 端
  SaaS**：面向养老机构与社区的分级照护管理能力（与东软同赛道但以软件成本优势切入）。

**8.3 场景外延（隐私模糊化的通用需求）**

- **宠物监控**：分享宠物动态时只展示火柴人，不暴露卧室场景（已有"宠物不需要隐私"类产品验证市场）；

- **养老院卧室 /
  卫生间**：原本禁装摄像头的区域可在隐私保护下安装，护工纠纷有据可查；

- **家门口监控**：模糊过路人画面；**车内哨兵模式**：识别车外行为而不记录行人面貌。

**附录 A：评委问答防御手册**

**Q1：这些功能规则引擎也能做，为什么需要 MiMo？**

A：规则能回答"发生了什么"，回答不了"该不该打扰、怎么开口、老人说的是什么意思、家属该做什么"。介入判断、含蓄语义理解、行动编排、日记生成四处是规则引擎的硬边界——移除
MiMo，Reme 就退化为传统报警器。

**Q2：和东软"火柴人"记录仪的区别？**

A：东软是 B 端监管工具，记录护理员行为合规，卖给机构与政府；Reme 是 C
端家庭关怀 Agent，理解老人需求并促成家属行动。赛道不同，能力层级不同。

**Q3：和亲鹿看护机的区别？**

A：两点：亲鹿异常时会切换真实高清录像，隐私有妥协，Reme
全程骨架为默认、原始影像分级授权；亲鹿止于告警电话，Reme
交付可执行的行动闭环。且亲鹿要买新设备，Reme 是纯软件。

**Q4：华为已有康养传感器，小米做这个晚了吗？**

A：华为证明了赛道价值，也说明小米"人车家"生态恰好缺这块原生能力。Reme
就是来补位的——而且用纯软件方案，补位成本最低。

**Q5：本地留存原始视频，是否违背隐私主张？**

A：这是刻意的"隐私分级"设计而非妥协：默认视图骨架、原始视频本地加密 7
天滚动删除、解锁需授权、全程留痕。 absolute
删除在举证场景（如养老院护工纠纷）反而不利于保护老人。我们把选择权交还给老人本人。

**Q6：你们的姿态识别准确率多少？**

A：感知层基于成熟开源姿态模型（33
关键点），我们自研的是上层异常行为规则引擎；演示环境的工程自测触发准确率
≥95%，口径在文档中如实标注，不做无依据的精度宣称。

**Q7：老人不愿意和 AI 说话怎么办？**

A：老人可随时说"不想聊了"或按键终止，系统立即结束且不追问；无响应时降级为仅记录日志 +
必要时通知家属。主动对话是增益，不是依赖。

**Q8：误报怎么控制？**

A：三重防线：事件规则的多条件联合判定（如跌倒需同时满足角度突变、重心骤降、持续低位）；MiMo
基于个人基线二次过滤；主动语音确认后再决定是否升级——误报在打扰家属之前就被拦截。
