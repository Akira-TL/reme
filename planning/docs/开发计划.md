# Reme 分步开发计划——以火柴人为中心的流水线视角（v3.0 对齐版）

> 口径基准：[Reme-核心产品文档-v3.0.md](Reme-核心产品文档-v3.0.md)（冻结版·唯一事实源）｜ 任务定义与验收：[任务分解.md](任务分解.md)（v3.0 修订版）｜ 增量依据：[v3.0-增量分析.md](v3.0-增量分析.md)
> 架构叙事不变：**上游把像素变成火柴人；中心是火柴人数据资产与契约；下游把火柴人变成事件、语义与行动。** 下游代码在物理上拿不到像素——这正是 v3.0 对外表达"隐私是数据边界"的工程实体。
> 本版变化：对齐 v3.0 六阶段重叠窗口（冻结提前到 0-4h）；删除 SAFE-10~13/UI-16/PER-09~11 相关排期；SAFE-14 故障注入与 PER-15 隐私断言升为必做；总量 156h，与容量基本打平。

## 1. 泳道定义

| 泳道 | 职责 | 主责 | 任务集 |
|---|---|---|---|
| **上游 · 骨架提取** | 像素 → 火柴人：采集、姿态推理、渲染、特征（含 zone 区域） | 梁博星 | PER-01/02/03/04、PER-16、DEL-11 |
| **中心 · 火柴人数据资产** | 事件 schema（v3.0 合同字段）、虚拟时钟、事件注入、双端脚手架与呈现 | 梁博星（实现）＋谭朗（按文档落地契约） | PER-05/08/12/13、UI-01/03、（PER-17/UI-14 待 D-10，默认不做） |
| **下游一级 · 火柴人 → 事件** | 规则引擎：长时间静止、疑似跌倒（＋去抖、阈值、状态恢复） | 梁博星 | PER-06、PER-07 |
| **下游二级 · 事件 → 语义与行动** | MiMo 认知编排（固定 JSON 合同）＋确定性安全兜底 | 谭朗（对话设计：江婷芳） | MIMO-01～17、SAFE-01～09、SAFE-14 |
| **下游三级 · 行动 → 呈现** | 家属端（六要素卡片＋处理状态流转）、老人端（对话＋文字降级 P0） | 李栋（家属端）＋梁博星（老人端） | UI-02/04/05/07/08、UI-09～13/15（UI-14 待 D-10 默认不做）、UI-17/19/20 |
| **保障线 · 演示与交付** | 剧本（v3.0 重写）、彩排、v3.0 验收表、PPT、视频、文档 | 江婷芳＋李栋（例外：DEL-07~09/13/25 谭朗、DEL-11/16/17 梁博星、DEL-12/26 谭朗定方案＋江婷芳执行） | DEL-01～26、G-01/04（G-03/05/07/09 随宿主任务归谭朗/梁博星） |

## 2. 三条并行原则（不变，且被 v3.0 强化）

1. **中心先行，契约即解耦**：v3.0 已把四组合同字段写进文档——冻结从"设计"变成"按文档落地＋四方签认"，所以窗口敢压到 **0-4h**。
2. **下游不等上游**：PER-13 注入接口是下游的"假上游"，注入事件与真实事件同 schema 同通路（`source` 字段区分），三模式演示（实时/剧本/录制）是 v3.0 P0 交付物。
3. **上下游只通过火柴人对话**：PER-15 自动化断言（"原始视频不进入任何网络请求"）已升为 **v3.0 必过验收项**——这条边界现在既是纪律，也是评分项。

## 3. 分步计划（5 步 · 3 个合龙点，对齐 v3.0 六阶段）

容量口径：每人可用约 35-38h/48h。v3.0 后总量 156h ≈ 容量上限，仍需按首裁项管理，但不再系统性超容。

**目标：契约按文档落地签认；未决决议全部拍板；最小链路起步。**

| 泳道 | 任务 | 产出 |
|---|---|---|
| 中心 | 谭朗 PER-05＋SAFE-01：按 v3.0 合同字段落地三契约＋四方签认 | shared/contracts 入库（S0 判据） |
| 中心 | 梁博星 UI-01 双端脚手架（全部 UI 的依赖，最先做）＋PER-01 采集起步 | 双端页面骨架可打开 |
| 下游 | 谭朗 MIMO-01 API 最小调用（耗时实测供 G-01） | API 可用性与延迟量级结论 |
| 保障 | 江婷芳统筹冻结会（30 分钟）：三场景定稿、隐私边界宣读、**D-02 通信选型 / D-05 场景 C 方式 / D-10 骨架回放去留 / D-07 遗留子项（加速豁免秒数、跌倒确认窗口与倒计时初值、多人入画、快捷键）**、D-06 任务 ID 对齐 → docs/decisions.md | 全部决议闭口 |
| 保障 | 江婷芳 DEL-01/02/03（12:00 前三项结论）＋G-04 调研页；李栋 UI-09 静态页起步＋DEL-22 PPT 骨架＋DEL-19 分镜表（按 v3.0 秒级分镜）——两者是 DEL-23/20 的依赖，不能晚于第 1 步 | **G-01 可行性实测汇总（12:00，API/帧率/合规——冻结版=事实 go，实测门槛不可跳过）** |

负载：全员 ≤4h ✅

**⛔ 合龙点 S0（4h）**：三契约签认＋决议清单闭口。v3.0 把冻结压到 4h 的底气是合同字段已在文档里——如果会上有人想改字段，答案是"改文档再改代码"，当场不辩论。

### 第 1 步（4–24h，v3.0 阶段②+③重叠）：上游造火柴人（4-16h），下游吃假火柴人（12-24h）

## 4. 每人一句话主线

- **梁博星 = 火柴人的人**：从像素造出火柴人（上游），管好它的基础设施（中心），让它变成两类事件（规则）。
- **谭朗 = 读懂火柴人的人**：按文档落地合同，让 MiMo 把事件变成 1-3 轮的自然确认与六要素行动，用状态机和故障注入证明"规则 > 大模型"。
- **李栋 = 呈现火柴人的人**：家属端讲好火柴人的故事——时间轴、六要素卡片与处理状态、告警、（日记 P1）。
- **江婷芳 = 校准所有人的人**：统筹 0-4h 冻结、对话与文字降级设计、口径仲裁（合同↔剧本↔界面↔PPT）、KPI 执行与对外叙事。**v3.0 后她不再是富余人力，排期已按贴满管理。**
